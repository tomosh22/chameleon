# WP-15: Header dependency handling

One branch (`wp/15-header-deps`), one PR. Diagnostics CML5550-5599 (`header_diag_ids.h`).

## How it works

`reload` -> sweep: the baseline reports the changed files (scan-tracked headers included) -> each changed file maps to compilands through the PDB list **and** the scan map -> PCH check -> cap check -> compile (progress per finished unit) -> per-compiland patches as before (WP-12). "Across modules": every enabled module has its own index and scan, and the service already loops over the modules, so a header used by several modules recompiles the including compilands of each. The cap is per module (see "Deferred").

Run the unit tests with the `unit.broker_core` and `unit.harness` ctest targets (portable); the scenarios with `cmltest --scenario tests/harness/scenarios/<name>.toml --require-all-capabilities` on Windows.

## Decisions

* **Dependency scan, not `/showIncludes`, as the primary source (ADR-0013 option 2).** A `/showIncludes` capture exists only after a recompile, but the first edit of a code-less header must already be found, and the baseline must already track that header: nothing tracks it otherwise (it is not in the clang-cl PDB list, so the sweep never even sees it change). So the scan runs at index time. It is textual and deliberately an over-approximation; the cost of a false positive is one extra recompile. `capture_includes` in the toolchain is left unused.
* **The PDB list is kept and united with the scan**, so nothing that worked before can be lost, and cl keeps headers the scan cannot resolve (SDK paths are not in `/I`).
* **System paths are neither tracked nor followed** (`is_system_path`, as for the baseline).
* **PCH header = everything a `/Yc` compiland lists or includes, except its own source.** The `/Yc` source itself still ends at CML2102 in the compiler rewrite, as before. CML2101 (planned in KNOWN_LIMITATIONS) is superseded by CML5550, which lives in the id range of this package and fires earlier.
* **The refusal does not move the baseline**: reverting the header makes the next reload a no-op.
* **Cap check after the PCH check, before any compile; per module.** The count is the number of compilands (not files).
* **`progress` is opt-in** so the three-event default of `subscribe` (asserted by an existing test) stays as it is.
* **Include search.** A quoted include is searched in the including file's directory, the directories of the files above it on the include stack (a file reached again with new directories is searched again), then `-I`. Comments are stripped with string, character and raw-string literals respected.
* **Diagnostics**: 5550 PCH header changed, 5551 too many compilands; 5552 a `/Yu` compiland's precompiled header cannot be determined (reload refused).

## Not done / limitations

* The scan is textual: `#include MACRO` is not followed; includes found only through the `INCLUDE` variable or compiler-built-in directories are not scanned (system headers); a changed `-I` list needs a rebuild and re-enable. See KNOWN_LIMITATIONS.
* Cap across modules: it is applied per module, because the modules are processed one after the other by the service and WP-16 changes that loop. A total over several modules is a small follow-up there.
* `/showIncludes` capture and a cache refresh after each recompile (exactness for conditional includes) were not built.
* The scan runs at index time; for projects with thousands of compilands this adds to the index load (progress is reported in the `scanning includes` phase). Not measured here.
