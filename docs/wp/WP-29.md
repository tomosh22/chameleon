## How to run

* Locally on Windows: `cmake --install build --prefix <dir>`, then `pwsh integrations/cmake/tests/run_examples.ps1 -BuildDir build -Work work -Config <cfg> -Compiler msvc`.
* ctest: `ctest -R cmake.enable` (configures a tiny project per case with the generator and compiler of the build).
* CI: step "WP-29 install tree and CMake examples" in every `build` cell and in `vs-generator`.

## Decisions

* **Link the agent although `Chameleon_API.h` loads the DLL at run time.** The brief asks for `Chameleon::agent` (and `lib/cml_agent.lib`). An import library nothing references adds no import to the exe, so it costs nothing at run time; its value is the include directory and the DLL copy. Fixtures pass `NO_AGENT` (they are also built standalone by cmltest, where no such target exists).
* **`EXPORT_NAME agent` and the include directory are set from `cmake/CmlInstall.cmake`**, not in `agent/CMakeLists.txt` (outside this package's directories): the agent's `PUBLIC` include dir is made `BUILD_INTERFACE` / `INSTALL_INTERFACE`.
* **Languages.** Under Ninja the compile flags are wrapped in single-language `$<COMPILE_LANGUAGE:C>` / `CXX` expressions so that resource compilers never see `/Gy`; the Visual Studio generators get plain options (they only feed ClCompile, and restrict `$<COMPILE_LANGUAGE>` to single-language targets).
* **`/Ob0` in every configuration but Debug** (the fixtures had it only in RelWithDebInfo). Release and MinSizeRel get a warning (CML1704) anyway.
* **`ALLOW_INLINING`** is the option for a target that is optimised on purpose. The `optimised` fixture keeps its own list-filter of `Ob0` (it still matches the module's option), so it was not edited (outside this package's directories).
* Non-x64 / unsupported compiler are errors; everything else that merely lowers the quality of the result is a warning that names the check id it would trip (`cml_broker check`).

## Deferred / limitations

* `chameleon_enable` is not applied to `static_lib` (fixture `static_lib`'s own `/Gy /hotpatch`) or `tests/unit/bind/edited`: they live outside this package's directories and keep calling `cml_target_fixture_style`.
* No arm64 / x86 support; CML1700 refuses them.
* CML1706 inspects `CMAKE_*_FLAGS`, linker flags and the options already on the target at the call; options added after `chameleon_enable` are not seen.
* The examples are built and audited, not run (running them needs a broker and a debugger-free session; the fixture scenarios cover running).
* clang-cl with the Visual Studio generator (`-T ClangCL`) is not covered by CI.
