# WP-32: Packaging, docs, licensing hook

## What was built

* **`tools/package/package.ps1`**: release build (RelWithDebInfo, `CML_FAULT_INJECTION=OFF`, `CML_BUILD_TESTS=OFF`, `CML_BUILD_GUI=OFF`),
  `cmake --install` into a staging directory (ADR-0038 layout `bin/ include/ lib/ lib/cmake/Chameleon/`), the two `.vsix` files under
  `integrations/`, `docs/`, `LICENSE`, the licence files of every vendored dependency (`licenses/third_party/<name>/`) plus
  `THIRD_PARTY_NOTICES.md`, the `examples/hello` program and `scripts/cml-reload.ps1`. Writes `MANIFEST.txt` (SHA-256 of every
  file), checks the content, zips to `chameleon-<version>-win64.zip` (entry names with forward slashes, one top folder). The
  version is read from `project(Chameleon VERSION ...)`.
  * Checks (fail the script with `WP32-CHECK FAIL ...`): required files present; no debug CRT imports, `_CrtDbgReport` or
    fault-injection strings (`inject-failure`, `fault-stages`, `fault-injection`, `injected failure at the stage`) in any `.exe`/`.dll`; the
    build's `CMakeCache.txt` has the promised options.
  * Parts that depend on unmerged work print `WP32-PENDING <part>` (install rules, the two `.vsix`, the CMake package, the
    CMake examples, `LICENSE`). `-Strict` makes any of them an error.
* **`tools/package/smoke.ps1`** (+ `tools/package/smoke/`, shipped as `examples/hello`): from the UNZIPPED tree only: verifies
  `MANIFEST.txt`, runs `cml_broker --version`, builds the example with `find_package(Chameleon)` + `chameleon_enable()`, runs
  `cml_broker check` (0 WARN required in package mode), starts `cml_broker --headless`, starts the example, edits `logic.cpp`,
  reloads with the packaged `scripts/cml-reload.ps1` and waits for the new value. Lines: `WP32-SMOKE manifest=ok`,
  `WP32-SMOKE build=ok find_package=true`, `WP32-SMOKE check=ok warn=0 fail=0`, `WP32-SMOKE reload=ok`, `WP32-SMOKE RESULT=PASS`.
* **`.github/workflows/package.yml`** (windows-2022; `workflow_dispatch`, `push` to main, `pull_request` on its own paths): runs
  the TROUBLESHOOTING check, `package.ps1`, uploads the zip (artefact `chameleon-win64`), unzips it into a clean directory,
  deletes the build tree and runs `smoke.ps1`.
* **`core/cml_license`**: `cml::license::Provider` interface, `Context`, `Status`, `check()`, `describe()`, `set_provider()`;
  the no-op provider always allows. `cml_broker --headless` asks once at start-up and logs `licence check: allowed (...)`. A
  refusal (CML5998) stops the broker with exit code 1, a failed check (CML5999) is a warning. Unit test `unit.license`.
* **Docs**: `docs/QUICKSTART.md` (fresh machine to first reload, zip only), `docs/TROUBLESHOOTING.md` (an entry for each of
  the 364 diagnostic ids defined in C++: cause, typical message, what to do, where raised), `docs/BUILD_REQUIREMENTS.md` (zip user
  section), `README.md` (overview and links).
* **Check that keeps TROUBLESHOOTING.md complete**: `tools/package/check_troubleshooting.cmake`, a ctest test
  `docs.troubleshooting` (runs in every `ci` cell) and a step of `package.yml`. It collects the ids (see the header of the script:
  `constexpr std::uint32_t kName = NNNN;` in `*ids.h`, `module_audit.h`, `fault_stages.h`, `pe_codeview.cpp`, and the bare numbers of
  `make_diag(` / `rewrap(` in `cml_pe` and `cml_coff`) and fails when one has no `### CMLnnnn` entry, when an entry is duplicated,
  or when fewer than 300 ids are found (the patterns rotted).

## How to run

```bat
powershell -File tools\package\package.ps1 -OutDir build\package
powershell -File tools\package\smoke.ps1 -Root <unzipped chameleon-X-win64> -Work <scratch dir>
cmake -DCML_SOURCE_DIR=. -P tools\package\check_troubleshooting.cmake
```

## What was learned

* Diagnostic ids are defined in four different styles (constants in `*_diag_ids.h`, constants in other headers, bare numbers in
  the PE/COFF readers, strings in harness code), so the check is deliberately a documented pattern list, with a floor on the
  number found. New ids written in the usual style are caught automatically.
* TROUBLESHOOTING.md was bootstrapped by a throw-away script that took the comment of each constant as "cause" and the message
  and advice of the first call site as "message" and "what to do". Entries without a recoverable advice sentence say so; they should
  be refined by whoever owns the id.

## Deferred / limitations

* No `LICENSE` file exists in the repository and the licence of Chameleon itself is not decided; the package reports
  `WP32-PENDING LICENSE` until one exists (`-Strict` fails).
* The GUI front-end (`cml_ui.exe`) is not in the package (`CML_BUILD_GUI=OFF`); WP-29's install rules decide what else is installed.
* The ids of WP-29 (CML17xx), WP-30/31 (CML5990-5997) are not defined in C++ and are described in a table in
  TROUBLESHOOTING.md; their owners add detail there.
* The `Failed` licence verdict does not stop the broker (fail-open); a commercial build may choose otherwise.
* The smoke test uses an example of its own (`examples/hello`) rather than WP-29's `integrations/cmake/examples`, which is copied to `examples/cmake` when present.
