# WP-03: End-to-end spike (M1 gate)

## What was built

`spike/`, a throwaway top-level directory (plus one `add_subdirectory(spike)` line in the top-level
`CMakeLists.txt`, an additive CI step and artifact path in `.github/workflows/ci.yml`, and
`/spike-work/` in `.gitignore`).

- `cml_spike.exe` (built with the repo's `/W4 /WX` helpers, reuses `cml_coff`, `cml_pe`, `cml_pdb`),
  one sub-command per step: `anchor`, `bind`, `reserve`, `load`, `retarget`, `hook`, `exercise`.
- `spike/run_spike.py`: the driver and every assertion. It is the "stub agent" orchestration:
  fixture `basic` runs **without** `--agent`; the spike process does `OpenProcess`, `VirtualAllocEx`,
  `CreateRemoteThread(LoadLibraryW)`, `WriteProcessMemory`, `SuspendThread`/`GetThreadContext`,
  `FlushInstructionCache` from outside.
- `spike/README.md`: the demo as a script (exact commands).
- CI: step "WP-03 spike" in the 8-cell matrix job (after `cml_pdb_dump`, before the artifact upload,
  so that earlier evidence steps still run if the spike fails). It fails the job on any assertion.
  `spike-work/` (obj, anchored obj, binding.obj, patch DLL/PDB, all logs, fixture stdout, raw cdb output)
  is uploaded in the existing `logs-<os>-<compiler>-<config>` artifact.

Pipeline (each step logs what it did, with addresses):

1. Start `fixture_basic.exe`, wait for `value=1`.
2. Copy `logic.cpp`/`logic.h` to a temp dir, `git apply --ignore-whitespace edits/value_2.edit`, recompile
   with the cell's compiler: `/c /Z7 /Gy /hotpatch /EHsc /GR /std:c++20` + defines + (Debug `/MTd /Od /Ob0 /RTC1`,
   RelWithDebInfo `/MT /O2 /Ob0 /DNDEBUG`). The fixture's real command line (from `compile_commands.json`) is logged.
3. `anchor`: rewrite `logic.obj` adding `__cml_anchor_<n>` (external) and `__cml_sanchor_<n>` (static) at offset 0
   of every non-debug section. `bind`: classify every undefined external against the fixture's PDB publics and
   emit `binding.obj` (16-byte `FF 25 rel32` thunk + 8-byte `__cml_slot_<name>` per function; 8-byte placeholder per data symbol).
4. `reserve`: scan with `VirtualQueryEx`, probe with `VirtualAllocEx(MEM_RESERVE)` a 64 MB block at 64 KB granularity
   within 1.5 GB and REL32 reach of the image (chose the block directly below the image in every cell).
   Link `patch_1.dll` with the plan §4.6 command (`/DLL /NOENTRY /NODEFAULTLIB /DEBUG:FULL /INCREMENTAL:NO /OPT:NOREF /OPT:NOICF /FUNCTIONPADMIN /FIXED /DYNAMICBASE:NO /BASE:<reserved> /PDB /OUT /IGNORE:4001,4254,4281`).
5. `load`: path buffer allocated, reservation released, remote `LoadLibraryW`, module list checked: loaded exactly at `/BASE`.
6. `retarget`: open the patch PDB with `cml_pdb`, find every anchor and slot in the publics, write the REL32/ADDR64 fix-ups
   (in-place addend honoured, int32 range checked) and the old function addresses into the slots; read-back verified.
7. `hook`: suspend all threads, RIP vs the 5-byte window, `E9 rel32`, `VirtualProtectEx`, flush, resume.
8. Asserts: `value=2` within 5 s, no `value=1` after the first `value=2`, strictly increasing `n`, process alive.
9. `cdb -pv` (ADR-0011): module with PDB symbols, `patch_1!compute_value`, `logic.cpp @ 8`, old entry is `jmp patch_1!compute_value`.
10. `exercise`: set the fixture's `g_tick` to 0; the patched function must read the OLD `g_tick`, take its branch and call
    the OLD `fixture_note()` through thunk + slot: `NOTE logic-start` must appear. (Without this, the thunk path would not
    be run at all, because `g_tick` is already large when the hook is installed.)

## How to run

`spike/README.md`. In CI: step "WP-03 spike (replace compute_value in the running fixture)".

### Externals of `logic.obj` (all classified through the fixture PDB publics)

| Compiler / config | externals seen |
|---|---|
| cl Debug (both generations) | `?fixture_note@@YAXPEBD@Z` (function), `?g_tick@@3HA` (data), `_RTC_InitBase` (function), `_RTC_Shutdown` (function) |
| cl RelWithDebInfo | `?fixture_note@@YAXPEBD@Z`, `?g_tick@@3HA` |
| clang-cl Debug and RelWithDebInfo | `?g_tick@@3HA`, `?fixture_note@@YAXPEBD@Z` |

`_RTC_*` come from `.rtc$IMZ`/`.rtc$TMZ` COMDATs (ADDR64 pointers) in cl Debug. They are bound with thunks and slots like any
function. No `__security_cookie`, `__security_check_cookie`, `__GSHandlerCheck`, `__CxxFrameHandler*`, `__imp_*`, no weak externals.

### Anchors

External anchors are found via **publics** (`find_public`), 100%: 4 to 7 per cell. Static anchors (`__cml_sanchor_<n>`) are found
neither in the publics nor in the module symbols (0 of 6..7). A function COMDAT's leader and its section anchor have equal RVAs
(cross-check passes). Module symbols of the patch contain only `compute_value` (`S_GPROC32`).

### Padding evidence for WP-10

6 bytes before every entry are `0xCC` in all cells (cl Debug: 7 `CC`, cl Release: 8, clang-cl: 16). This does not prove
`/FUNCTIONPADMIN` since 16-byte function alignment gives the same bytes. cl on x64 ignores `/hotpatch` (D9002), clang-cl shows no
2-byte NOP either: entries begin `40 57 48 83 ec 20` (cl Debug), `48 83 ec 28` (others). The 5-byte jump splits the instruction at the entry in every
cell; the remaining bytes are never executed. Only one thread existed in the fixture; the retry path (RIP inside the window) was not exercised.

## What was learned

See `docs/DECISIONS.md` ADR-0020 (surprises, one by one). Highlights: anchors must be external; REL32 in-place addends (clang-cl -1);
function/data classification must come from the PDB, not from the object; `/FIXED` + remote `LoadLibraryW` works everywhere; no linker
warnings; clang-cl cells use lld-link; cdb needs `.reload /f`.

Tricky in the anchor rewriter (WP-06 must handle): new symbols appended after the original ones; string table must be last in the file
and its leading size field and the header's `NumberOfSymbols` rewritten; name offsets include the size field; refuse bigobj; skip
`.debug*`, `.drectve`, `LNK_REMOVE` sections.

## Deferred, with reasons

- Bigobj anchors/bindings, COMDAT-selection rewriting, weak externals, COMMON symbols: not needed for `logic.cpp`, spike fails loudly.
- Non-trivial externals (`__security_cookie`, `__CxxFrameHandler*`, `__imp_`): classification code exists (publics, import table), not
  run on real input here.
- Thread-race retry, instruction-boundary decoding, trampoline restore: WP-10. Reservation pool and unload on failure: WP-08.
- `ADDR32NB` to data and TLS (`SECREL`): reported as a problem, not handled (WP-24).
- Real diagnostics ids (`CMLnnnn`): the spike prints plain messages.

Files outside `spike/`: `CMakeLists.txt` (one line), `.github/workflows/ci.yml`, `.gitignore`, `docs/DECISIONS.md` (ADR-0020 appended), this file.
