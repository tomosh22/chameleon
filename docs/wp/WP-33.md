# WP-33: chameleon_enable without compiler warnings

(ADR-0040.)

## What changed and why

With cl on x64 every TU of an enabled target printed `D9002 ignoring unknown option '/hotpatch'`, and in
RelWithDebInfo `D9025 overriding '/Ob1' with '/Ob0'`.

- `integrations/cmake/ChameleonEnable.cmake`: `/hotpatch` is passed to clang-cl only (cl accepts it on x86 only, and
  `chameleon_enable` supports x64 only). On x64 cl the padding comes from `/FUNCTIONPADMIN` (link option, unchanged).
- `/Ob1` and `/Ob2` are removed from `CMAKE_C/CXX_FLAGS_RELEASE|RELWITHDEBINFO|MINSIZEREL` before `/Ob0` is added
  (skipped with `ALLOW_INLINING`). CMake has no per-target way to remove a configuration flag, so this is a
  deferred call (`cmake_language(DEFER DIRECTORY <target's directory>)`, once per directory, so it works from any function
  depth) that edits the variables in directory scope (never the cache). Side effect, documented in
  `docs/BUILD_REQUIREMENTS.md`: other targets of that directory lose their default `/Ob1`/`/Ob2` too, also one with
  `ALLOW_INLINING`. Called from a parent directory for a subdirectory's target it is too late: warning CML1712.
- `/hotpatch` is chosen per language with `$<COMPILE_LANG_AND_ID:<lang>,Clang>` (a C-only project has no CXX id).
- `cmake/CmlTargets.cmake` `cml_target_fixture_style`: same removal for RelWithDebInfo.
- Check rule: CML1601 never required `/hotpatch`; it samples function padding in the image. Only its documentation
  (`docs/BUILD_REQUIREMENTS.md`) was corrected. No broker change.
- CI: step "WP-33 no D9002 or D9025" in the `build` job, after the WP-29 examples step.

## Flags before and after (x64, Ninja)

| Compiler | Config | Before | After |
|---|---|---|---|
| cl | Debug | `/Gy /hotpatch` | `/Gy` |
| cl | RelWithDebInfo | `/O2 /Ob1 ... /Gy /hotpatch /Ob0` | `/O2 ... /Gy /Ob0` |
| clang-cl | Debug | `/Gy /hotpatch` | `/Gy /hotpatch` |
| clang-cl | RelWithDebInfo | `/O2 /Ob1 ... /Gy /hotpatch /Ob0` | `/O2 ... /Gy /hotpatch /Ob0` |

Link flags are unchanged: `/DEBUG:FULL /INCREMENTAL:NO /OPT:NOREF /OPT:NOICF /FUNCTIONPADMIN`.

`/hotpatch` in fixtures (static_lib, bad_builds, bind/edited, coff) and `/Ob1` surviving because `chameleon_enable` and
`cml_target_fixture_style` run inside caller functions (their `PARENT_SCOPE` stops at the function) were the causes; the
second run (05b083a) still had `d9025=11` from `tests/unit/bind/edited` and `tests/unit/coff`. Fixed in ec7aa57:

  `corpus` 45210469247 green.

  RelWithDebInfo).

  `exe_plus_dll ... check=PASS warn=0 modules=2`, in every cell.
