# WP-05: Toolchain command parsing and rewriting

## What was built

`core/cml_toolchain` (headers in `include/cml/toolchain/`, umbrella `toolchain.h`):

| Header | Content |
|---|---|
| `command_line.h` | Windows tokeniser (CommandLineToArgvW rules), `quote_argument` / `join_command_line`, clang's cc1 quoting (`split_command_line_posix`), `@response` files (UTF-8/UTF-16 BOM, nested, depth 8, injectable file reader). |
| `record.h` | `CompileRecord` (cwd, compiler, args without program, source, recorded PDB), `record_from_build_env(cml::pdb::BuildEnv)`, `Dialect` (Cl, ClangClDriver, ClangCc1), `detect_dialect`. |
| `compile_commands.h` | Hand-written bounds-checked JSON reader (depth 64, 512 MiB cap), lookup by absolute source path, `record_from_compile_command`. No third-party dependency. |
| `rewrite.h`, `src/rules.cpp` | `rewrite_for_patch()` and the rules as data (`Rule{match, pattern, action, replacement, consume_next, tag, diag, warn_diag, why}`; three tables: `cl_rules`, `clang_cl_extra_rules`, `cc1_rules`). `patch_object_path()` = `<session_tmp>\<module>\<hex16 hash>\<stem>.obj`. |
| `tool_info.h` | `ToolFamily` (cl, clang-cl, clang, link, lld-link), `parse_tool_banner`, `locate_tool`, `detect_tool` (runs the binary, falls back to the version resource), `read_file_version`. |
| `build_flags.h` | Per-compiland facts for `/GL`, `/Gy`, `/hotpatch`, `/guard:cf` with the evidence source; module-level `/guard:cf` from the PE; `classify_object` (COFF / bigobj / IL / LLVM bitcode). |
| `invoke.h` | `CancelToken`, `run_parallel` (pool of `min(jobs, hardware_concurrency)`), compiler-output parser (`file(line,col): error CODE: msg`), Windows only: `run_process` (CreateProcess, one pipe for stdout+stderr, job object kill, timeout, `@rsp` for long command lines), `compile_tu`, `compile_all`. |
| `symbol_set.h` | Defined/undefined/weak/static symbol sets of an object and their diff (the acceptance check). |

Tools and tests: `cml_tc_probe` (CI evidence tool), `tests/unit/toolchain` (`unit.toolchain`), fixture
`tests/fixtures/pch`, `tests/ci/clang_version_probe.ps1` and the `clang-versions` CI job.

## How to run

* `ctest --test-dir build -C <cfg> -R unit.toolchain -V` (the `-V` output carries the `RECORDED`, `PCH-STRATEGY`, `FLAGS`, `TOOL` evidence lines).
* `build/bin/cml_tc_probe commands <exe|pdb> [--obj-dir DIR]`, `recheck <exe|pdb> --obj-dir DIR [--pch-mode auto|z7|keepzi|nopch] [--translate-cc1]`, `detect`, `flags <exe>`, `driver-compile ...`.
* Portable parts build and test on any host with `-DCML_ALLOW_NON_WINDOWS=ON` (everything except `run_process`, `compile_*`, `detect_tool`).

## Decisions

### Recorded commands come from S_BUILDINFO, and cl's strings are split (WP-04 bug fixed here)
Neither compiler emits S_ENVBLOCK in any tested version (table below). cl splits its long command line into
`LF_STRING_ID` pieces. `llvm-pdbutil dump --ids` of a cl 19.51 PDB showed three plain `LF_STRING_ID`
(`0x1021..0x1023`), a `LF_SUBSTR_LIST [0x1021 0x1022 0x1023]` and a final `LF_STRING_ID {id 0x1024, string " Kits\... -X"}`:
the pieces of the substring list come first and the record's own text is the **last** piece.
`cml_pdb`'s `ipi_string()` appended the own text first, which scrambled every long cl command. Fixed in
`core/cml_pdb/src/index_symbols.cpp` and in the two synthetic tests that had encoded the wrong order
(`tests/unit/pdb/test_util.h`, `test_synthetic.cpp`). **These are files outside `core/cml_toolchain`** (WP-04 owns them); the change is
one function. The orchestrator should record it against WP-04.

The recorded cl command has no `/Fo`, `/Fd` or source file, starts with `-nologo -TP ...`, contains the `%INCLUDE%` directories as quoted
`-I"..."` options after `-c`, and ends with `-X`; it is normalised to `-` options (`-Zi`, `-Yu...`). The source is in the `src` key and appended by the rewriter.

### cc1: replay (option a) is the decision
clang-cl records the **cc1** command (`"-cc1" "-triple" ...`) quoted the way `llvm::sys::printArg` quotes (backslash escapes `"`, `\`, `$`, `` ` ``: `D:\\proj` is `D:\proj`), so
cc1 commands are tokenised with `split_command_line_posix`; every other command uses the Windows rules.

* **(a) replay** `<recorded compiler> -cc1 <rewritten args>`: `-o` replaced, depfile options (`-dependency-file -MT -MQ -sys-header-deps -dependency-filter`, `--show-includes`) dropped, `-fcolor-diagnostics` dropped, LTO options dropped with CML2210, `-emit-pch`/`-building-pch-with-obj` refused with CML2102, `-gcodeview-command-line` added when debug info is on so a patch object can be re-read.
  Evidence: for fixture `basic` (main, logic, extras) and `pch` (main, logic) under clang-cl 20 in Debug and RelWithDebInfo, and under clang-cl 17.0.6, 18.1.8, 19.1.7, 20.1.8 built by hand, **every replayed object has exactly the original symbol set** (`RESULT <stem> OK n symbols match`, `cc1_replay_recheck_exit=0` in all four `clang-versions` cells; `unit.toolchain` fixture tests in the 4 clang-cl matrix cells).
* **(b) translate cc1 back to a driver command** (prototype `cml_tc_probe recheck --translate-cc1`): cc1 has options the driver has no spelling for (`-D_MT`, `-stack-protector 2`, `-vectorize-*`, `-mllvm ...`, `--dependent-lib=...`, ...); the prototype maps `-D/-I/-std/-O/--dependent-lib` and passes the rest as `/clang:`, and in the clang-cl 20 RelWithDebInfo cell it produced **different symbol sets** (`main`: MISMATCH; `extras`: `only in second: defined_external: ??1runtime_error@std@@UEAA@XZ`; `6 cc1 options with no mapping`). Translation is lossy by construction.
* The **driver form** (compile_commands.json from CMake with clang-cl, `Dialect::ClangClDriver`) uses the cl rule table plus `clang_cl_extra_rules`; `/clang:-gcodeview-command-line` is added. `cml_tc_probe driver-compile` compiled a driver-form record successfully with 17.0.6, 18.1.8, 19.1.7 and 20.1.8.

### `/Zi` -> `/Z7` with a precompiled header (fixture `pch`, cl 19.44 and 19.51 in CI)
`PchDebugMode` has three strategies; evidence from `unit.toolchain` / `cml_tc_probe recheck --pch-mode ...` on the windows-2025 cl RelWithDebInfo cell (run 40165150795):

| Strategy | Result for the `/Yu` TUs `main` and `logic` |
|---|---|
| `ForceZ7` (`/Zi` -> `/Z7`, keep `/Yu /Fp`) | **fails**: `error C2855: command-line option '/Z7' inconsistent with precompiled header`, `C1903` |
| `KeepZiPrivatePdb` (keep `/Zi`, `/Fd` = private copy of the recorded compiler PDB, keep `/Yu /Fp`) | **works**, symbol set identical to the original, 0.11-0.16 s per TU |
| `DropPch` (`/Z7`, drop `/Yu /Fp`, keep the forced include) | compiles but the symbol set is **not** equivalent: extra defined externals (`??$_Digit_pairs@D@std@...`, `_Avx2WmemEnabledWeakValue`), 0.9 s per TU |

Decision: `kDefaultPchDebugMode = KeepZiPrivatePdb`. TUs without `/Yu` always get `/Z7`. The private PDB copy is made by `compile_tu` from the recorded `pdb` key (`vc140.pdb`) or `/Fd`; a missing source PDB is warning CML2211. clang-cl has no such distinction (its `/Zi` and `/Z7` are the same) and all strategies pass there. The `/Yc` TU is refused with CML2102 (message from `docs/KNOWN_LIMITATIONS.md`) under cl (`-Yc`) and clang (`-building-pch-with-obj`), asserted in the fixture tests.

### Rewrite rules (plan 4.4)
`/Zi`,`/ZI` -> `/Z7` (`/ZI` also adds `/Gy`, which it implied); dropped: `/Fd /FS /Gm /MP[n] /showIncludes /sourceDependencies[:] /experimental:log /analyze /Fo /Fe /Fa /FA /Fm /FR /Fr /c /nologo /link ...`; `/GL` -> `/GL-` with CML2210; `/clr`, `/ZW` -> CML1504; `/Yu /Fp /FI` kept; everything else verbatim. `/sourceDependencies <file>` and `/experimental:log <file>` take the next token (found in a real UnrealBuildTool `.rsp`). Output `/Fo<out>`, `/c`, `/nologo` and the source are added once. Response files are expanded before the rules run. The table in `rules.cpp` is the documentation; `unit.toolchain` checks every rule is documented and well-formed.

### Invocation
Exact recorded compiler binary and cwd; missing -> `locate_executable`/`locate_tool` on `fallback_search_dirs` then PATH, warning CML2201 (tested with a removed path, and with fallback disabled -> CML2202). `CreateProcess` with only the pipe and `NUL` inherited (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, so parallel launches cannot leak each other's pipe), job object with `TerminateJobObject` for cancel and timeout (not `KILL_ON_JOB_CLOSE`: cl `/Zi` may start a shared `mspdbsrv.exe`), `@rsp` (UTF-8 BOM) when the command line exceeds 30000 characters or `force_response_file` (tested against real cl and clang-cl). Output is re-emitted as `file(line,col): error CODE: message`; a failing compile is CML2200 whose message carries the first error. `CancelToken` cancels many processes; `run_parallel` is the pool.

### Build-flag detection (plan section 13 Q1, decided with evidence)
`detect_compiland_flags()` returns `FlagFact{value, evidence, detail}`:

| Flag | Order of evidence | CI evidence |
|---|---|---|
| `/GL` | recorded object format (`classify_object`: anonymous non-bigobj header = IL, `BC C0DE` = bitcode, else COFF) > `S_COMPILE3` LTCG bit > command line (`/GL`, `/GL-`, clang `-flto*`; **not** `-flto-visibility-public-std`, which every clang-cl cc1 command contains) > absent = No | fixtures: `No (object-format)` in every cell |
| `/Gy` | explicit `/Gy` / `/Gy-` / cc1 `-ffunction-sections` > object (every defined function in a COMDAT section; for cl a `NoDuplicates` COMDAT is required because inline functions are COMDAT without `/Gy`) > implied (cl: `/ZI`, `/O1`, `/O2`; not for clang-cl) > absent = No | fixtures: `Yes (command-line)`; with only the object: `Yes (object-sections)` (first cl run) |
| `/hotpatch` | command line > `S_COMPILE3` bit | **The bit is set for cl and clang-cl x64 objects whatever the command line says**; cl ignores `/hotpatch` on x64 (D9002, ADR-0020) and the recorded cl command has no `-hotpatch`. So the fact means "x64 function entries are patchable", not "the option was passed"; the detail string says so. |
| `/guard:cf` per compiland | command line (`/guard:cf`, `-cfguard`) | `No (command-line-absent)` |
| `/guard:cf` per module | `DllCharacteristics` GUARD_CF + non-empty load-config function table (never `GuardFlags` alone, ADR-0015) | fixture exes: `No`, detail "CF_INSTRUMENTED comes from the CRT libraries only" |

WP-18 turns these into CML1103/1104/1105.

### Tokenising oddities seen in real data
* cl PDB commands are properly quoted; the earlier "unquoted include directory" suspicion came from the piece-order bug above and was removed again.
* clang cc1 uses POSIX-style escapes inside double quotes (see above).
* clang-cl 20 records `--show-includes` (double dash).

## clang version table (job `clang-versions`, MSVC STL 14.44, fixture `basic` with `/Zi`, link.exe `/DEBUG:FULL`)

| clang-cl | S_ENVBLOCK | S_BUILDINFO | command | cc1 replay (a) | `-gno-codeview-command-line` | driver-form compile |
|---|---|---|---|---|---|---|
| 17.0.6 | absent | yes | cc1 | 3/3 symbol sets match | S_BUILDINFO without a command | ok |
| 18.1.8 | absent | yes | cc1 | 3/3 match | same | ok |
| 19.1.7 | absent | yes | cc1 | 3/3 match | same | ok |
| 20.1.8 | absent | yes | cc1 | 3/3 match | same | ok |

No flag is needed: `-gcodeview-command-line` is on by default in all four. **Minimum supported clang: 17.0.6** (the oldest tested; the plan asked for 17-20; older releases were not tested). S_ENVBLOCK is never emitted, so S_BUILDINFO is the only source (plan section 13 Q3 answered: no version drops S_ENVBLOCK, it was never there).
Note: the runners' MSVC STL (14.44+) refuses clang older than 19 (`STL1000`); 17 and 18 need `/D_ALLOW_COMPILER_AND_STL_VERSION_MISMATCH`, which the probe passes. The project's own build is unaffected (matrix cells use the runner's clang 20).

## Acceptance
1. **Table-driven corpus**: `tests/unit/toolchain/command_corpus_cases.inc`, 59 cases, each asserting tokenisation, rewritten command and diagnostics (`unit.toolchain`). Producers: CMake+Ninja, CMake+MSBuild/MSBuild CL task, FASTBuild, Unreal UBT, clang-cl driver and cc1. **9 are real** (3 from public UBT `.rsp` / FASTBuild `.bff` files found with GitHub code search: `L1ngan/EasternEraMod` UnLua `*.obj.rsp` (UBT, `/Yu /Fp /FI /experimental:log /sourceDependencies /d2ssa-cfg-question-`), `caveman2cosmos/Caveman2Cosmos` `Sources/fbuild.bff` (a verbatim cl line with `/Yu` and `/Yc`); 6 captured from CI: cl 19.51 Ninja basic/pch (Yu, Yc) and clang-cl 17/18/19 cc1). The rest are **constructed** from documented syntax in the style of the named producer (MSBuild CL task, FASTBuild `.CompilerOptions` templates of public repositories with `%1/%2` substituted, CMake VS-generator spellings); each case's `source_of_line` says which. The licences of the public repositories were not checked: only short flag lists (facts about a build) were used. No MSBuild-generated command was captured (the VS-generator job builds with MSBuild but does not run the probe).
2. **Fixture recompile** (`test_fixture_recompile.cpp`): every TU of `basic` and `pch` recompiled from its PDB record, symbol set compared with the original `fixture_*_objs` object, in all 8 cells and the VS-generator job. Also: compiler-missing fallback, `@rsp`, clickable errors with CML2200, flag facts, tool detection.

## Diagnostics (to fold into `docs/KNOWN_LIMITATIONS.md` / ADR-0008 ranges)
CML1500 response file unreadable, 1501 response files nest too deeply (also cycles), 1502 compiler is not cl/clang-cl/cc1, 1503 no source file in the command, **1504 `/clr` or `/ZW` cannot be hot-reloaded (by design)**, 1505 compile_commands.json malformed, 1506 unreadable, 1507 no entry, 1510 tool not found, 1511 tool detection failed, 1520 object unreadable (reserved);
CML2200 compile failed (diagnostics in `CompileOutcome`), 2201 recorded compiler missing, fallback used (warning), 2202 cannot start / no compiler, 2203 cancelled, 2204 timeout, 2205 no object produced, 2206 cannot prepare output, **2210 `/GL` or LTO removed for the patch compile (warning; the patch code may differ from the original)**, 2211 compiler-PDB copy failed (warning); **CML2102 `/Yc` TU changed** and **CML1102 no recorded command** are raised here with the registered messages.

## Deferred / not done
* Nothing is hooked into a broker pipeline (WP-12); `compile_all` is tested only through `run_parallel` plus the single-TU path, not with several real compiles at once.
* `PchDebugMode::DropPch` is kept as an option but not equivalent; not used.
* Header-to-compiland mapping for clang (ADR-0013): `capture_includes` exists (`/showIncludes` or `-show-includes`, parsed by `parse_show_includes`) but is not wired.
* ANSI-codepage response files are passed as bytes (no code page conversion).
* `/Fo` with a relative `output_object` is resolved by the compiler against the recorded cwd; callers must pass absolute paths.
* MSVC-generator (MSBuild) command lines were not captured; the VS-generator CI job only runs the unit tests.
* clang driver (`clang.exe` gnu-style) and `clang-cl /clang:-Xclang` edge cases beyond the table are not supported.
