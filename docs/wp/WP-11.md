# WP-11: Agent skeleton, public header and IPC

## What was built

- **`core/cml_ipc`**
  - `messages.h/.cpp` (portable): frame `uint32 payload_size, uint16 type, uint16 version, payload`, all
    little-endian; `payload_size` counts the bytes after the 8-byte header; hard limit 1 MiB per frame, 256 KiB
    per string, 16384 modules per list. Hand-written bounds-checked (de)serialisers; strings are validated
    UTF-8; trailing bytes, lying counts and unknown enum values are rejected.
  - `pipe.h/.cpp` (Windows): overlapped byte-mode named-pipe transport for agent and broker
    (`PipeConnection`, `PipeServer`, `connect_pipe`, `resolve_pipe_name`). Timeouts, sticky `cancel()`, a
    caller wake event, partial frames preserved across timeouts.
- **`core/cml_proc`**: module enumeration (toolhelp), logon-session and user SID, env access, UTF-8/16
  conversion, command line, `diag_ids.h` (registry of all CML52xx ids).
- **`agent/`**: `cml_agent.dll` (exports, DllMain, operator new/delete -> private heap) on top of
  `cml_agent_core` (agent thread, request table, SyncQueue, module diff, broker launch, logging, heap).
  `Chameleon_API.h` is header-only (C99 + C++ wrapper); it LoadLibrary()s the agent and checks the ABI version.
- **`broker/cml_core`**: `Session` (portable per-agent state machine) and `ConnectionServer` (thread per
  connection, idle/startup timeouts). **`broker/cml_cli`**: `cml_broker --headless [--pipe N]
  [--exit-when-idle MS] [--startup-timeout MS] [--log FILE] [--verbose]`.
- **Tests**: unit tests per library, header gates (C99, C++14, C++20, each also "bare" without
  `WIN32_LEAN_AND_MEAN`/`NOMINMAX`), fixture `c_only`, `--agent` for fixture `basic`, and the process-level
  driver `tests/integration/agent_driver.cpp`.

## How to run

`ctest --test-dir build -C <config> --output-on-failure`. Relevant tests: `unit.ipc`, `unit.proc`,
`unit.agent` (end-to-end through the public header against an in-process broker), `unit.broker_core`,
`header.cml_header_check_*`, `fixture.c_only.runs`, `integration.agent_enable_module`,
`integration.agent_autostarts_broker`, `integration.agent_without_broker_runs`,
`integration.c_only_agent_enable_module`, `integration.c_only_agent_autostarts_broker`.
By hand: `cml_broker --headless --pipe \\.\pipe\x`, then `set CML_PIPE_NAME=\\.\pipe\x` and
`fixture_basic --agent --ticks 20`. Integration logs land in `<build>/test_work/integration/`.

## Message type ids (stable)

Hello 0x0001, Welcome 0x0002, Reply 0x0003; ModuleList 0x0010, EnableModule 0x0011, DisableModule 0x0012,
ModuleLoaded 0x0013, ModuleUnloaded 0x0014; ReserveRange 0x0020, ReleaseRange 0x0021; LoadPatch 0x0030,
PatchLoaded 0x0031, ApplyFixups 0x0032, RunInitializers 0x0033; InstallHooks 0x0040, HooksInstalled 0x0041,
SyncPointReady 0x0042; Exception 0x0050, ExceptionAction 0x0051; Log 0x0060, Restart 0x0061.
Only Hello, Welcome, Reply, ModuleList, EnableModule, DisableModule, ModuleLoaded, ModuleUnloaded and Log
have payloads; the rest decode to CML5203. Payload version is 1 for all. Requests carry a `request_id`;
Welcome and Reply repeat it (Reply: `uint32 status`, 0 = OK, else the CMLnnnn number, plus UTF-8 text).
ModuleLoaded/Unloaded/Log are events with no answer.

## Diagnostic ids (CML5200-5299)

| id | meaning (message) | what to do |
|---|---|---|
| 5200 | frame header invalid / payload above 1 MiB | use agent and broker from the same build |
| 5201 | malformed payload (truncated, trailing bytes, bad count/enum, invalid UTF-8) | same |
| 5202 | payload version unsupported | same |
| 5203 | message type unknown or not implemented in this build | same |
| 5204 | message too large to send (string or payload over limit) | shorten the path/text |
| 5205 | cannot connect to broker pipe | start cml_broker or set CML_PIPE_NAME |
| 5206 | pipe I/O failed (OS error) | restart app and broker, report with log |
| 5207 | cannot create the pipe (name taken by another process, or security setup failed) | stop the other broker / use another `--pipe` |
| 5208 | pipe name lacks `\\.\pipe\` prefix | fix CML_PIPE_NAME / `--pipe` |
| 5209 | pipe served by another user, or server cannot be verified | stop that process or use another name |
| 5210 | handshake failed (protocol mismatch, no Welcome in 5 s) | use matching versions |
| 5211 | cannot start cml_broker.exe | set CML_BROKER_PATH or start the broker manually |
| 5212 | EnableModule: module `X` is not loaded in process N | load it / pass its full path |
| 5213 | DisableModule: module is not enabled | call EnableModule first |
| 5214 | protocol violation (message before Hello, second Hello, broker-only message) | report as bug |
| 5215 | request cancelled: agent destroyed before the answer | n/a |
| 5216 | connection lost before the broker answered | the agent reconnects; resend |
| 5217 | too many outstanding requests (1024 open, plus 256 reserved for re-enables) | collect answers with wait_request |
| 5218 | agent thread/event could not be created | free system resources |
| 5220 | cannot enumerate modules of process N | check the process exists |
| 5221 | cannot query token/SID | run as the same user |
| 5290-5297 | header status codes: NOT_IMPLEMENTED, ABI_MISMATCH, AGENT_NOT_FOUND, INVALID_ARGUMENT, AGENT_LOAD_FAILED, NOT_CONNECTED (reserved), TIMEOUT, UNKNOWN_REQUEST | see `Chameleon_API.h` |

By-design limitations for the orchestrator to fold into KNOWN_LIMITATIONS: the agent DLL is never unloaded
once started (later hooks point into it); module changes are noticed with up to 500 ms delay (polling), but
the list is always refreshed before an EnableModule/DisableModule is sent; `ScheduleReload`, `WaitForReload`,
`ScheduleRestart`, `SetGlobalHotkeys` return CML_STATUS_NOT_IMPLEMENTED (5290); the hook macros are WP-17.

## Design decisions

- **Pipe security.** Server: `CreateNamedPipe` with a protected DACL `D:P(A;;GA;;;<current user SID>)`
  (one ACE, nothing inherited, so only the creating user - not other users, not SYSTEM/Administrators unless
  they are that user), `PIPE_REJECT_REMOTE_CLIENTS`, and `FILE_FLAG_FIRST_PIPE_INSTANCE` so a name that is
  already served cannot be taken over (also stops two brokers). Client: opens at
  `SECURITY_IDENTIFICATION` (server cannot impersonate it) and verifies the server process runs as the same
  user (`GetNamedPipeServerProcessId` + token SID compare), failing closed (CML5209).
- **Pipe name.** `\\.\pipe\cml_broker_<logon-session SID>`; overrides `CML_PIPE_NAME`, `--pipe`.
- **Module notifications: polling**, not `LdrRegisterDllNotification`. The agent thread snapshots modules
  every 500 ms and on every request, and sends ModuleLoaded/Unloaded from a diff. Reasons: the Ldr callback
  is undocumented-in-headers, runs under the loader lock where doing I/O or allocating is hazardous, and
  WP-10 needs the agent to stay quiet while threads are suspended (a poll can simply be skipped).
- **Heap strategy.** `operator new/delete` of the DLL are replaced (`operator_new.cpp`) to use a private
  `HeapCreate` heap (`heap.h`), created lazily, never destroyed. `set_alloc_forbidden(true)` makes any
  allocation abort with a message: the hook WP-10 flips while host threads are suspended. CRT `malloc` and
  Win32 internal allocations are not covered. Unit tests assert the live block count returns to baseline
  after create/destroy cycles.
- **Agent lifecycle.** `cml_agent_create` starts a thread via `_beginthreadex` and returns; connection,
  broker auto-start (`CML_BROKER_PATH`, else next to the DLL, `CML_BROKER_ARGS` appended, one launch per
  connection cycle, detached, no inherited handles), bounded back-off (50 ms doubling to 1 s), Hello,
  Welcome, ModuleList. Requests queued before the connection exists are sent afterwards. Replies are
  collected with `cml_wait_request` (timeout 0 polls). Warn/error agent logs are forwarded as `Log`.
- **SyncPoint.** Synchronised mode: atomic flag check, queued work runs on the caller's thread in order.
  Immediate mode: one branch in the header. Test hook: `cml_agent_testing_post_work` export.
- **ABI.** Version 2; header checks `cml_agent_abi_version`, all exports are resolved up front and missing
  ones also give ABI_MISMATCH. Exports are checked against the header typedefs with `static_assert`.
- Because the fixtures' `agent` DLL and `cml_broker.exe` sit in one output directory, the header finds them
  with the directory of the exe; no compile definition needed.

## Learned

- `doctest` `REQUIRE_MESSAGE(cond, a ? b : c)` needs parentheses around the ternary.
- A `//` comment ending in `\` continues onto the next line (`-Wcomment`); caught only by compiling.
- mingw-w64 + wine were available on the Linux build host and caught several bugs before CI (not a
  substitute for it; wine does not enforce `FILE_FLAG_FIRST_PIPE_INSTANCE`).

## Deferred

- Real broker features (WP-12), hook macros and patching (WP-10/17), reload/restart/hotkeys.
- `LdrRegisterDllNotification` (see above). Fuzzing of the decoders (WP-28; a pseudo-random smoke test exists).
- Per-process pipe-name collision between two logon sessions of the same user is not handled specially.

## Review fixes (second pass)

1. **Forwarded Log text is always valid UTF-8.** `ipc::utf8_cut_point` / `ipc::sanitize_utf8` cut on character
   boundaries and turn invalid bytes into U+FFFD; the agent's log sink uses them for every forwarded line (the C
   runtime cuts log lines at 1023 bytes, possibly mid-character), `fill_reply` and `describe` use the cut helper,
   and the encoder now refuses to put invalid UTF-8 on the wire (CML5201). On the receiving side a frame with a
   sound header but an invalid payload (CML5201..5203) no longer ends the connection: `PipeConnection::receive`
   consumes it and returns `IoStatus::Rejected` with the diagnostic; broker and agent log it and carry on. A
   broken header (bad length) still returns a Diag and closes.
2. **One bad client never stops the broker.** `accept()` treats `ERROR_NO_DATA` (client came and went) as
   disconnect-and-listen-again, `ERROR_PIPE_CONNECTED` as success; `ConnectionServer::run` tolerates failed
   accepts (logs, pauses, gives up only after 50 in a row).
3. **Enabled modules survive a reconnect.** The agent tracks the modules the broker accepted and the
   application did not disable, and queues an internal `EnableModule` for each ahead of everything else after
   every reconnect (a re-enable that fails drops the module from the set).
4. **No write/read deadlock.** At most 16 requests are in flight; the agent loop reads replies between flushes.
   The request table holds up to 1024 entries (queued, sent and uncollected answers).
5. **Full module paths.** The toolhelp snapshot's `szExePath` is cut at MAX_PATH; the path is now read with
   `GetModuleFileNameW` (own process) or `K32GetModuleFileNameExW` (other processes) through
   `proc::read_growing_string`, which grows the buffer up to 32768 characters.
6. **Failed creates.** Chosen: after the agent DLL's create function has been called the header never unloads
   the DLL (consistent with never-unload). A failed create leaves the DLL loaded; retries reuse it and
   initialise nothing twice (private heap, log sink). Only a DLL that fails the ABI check is unloaded. Tested:
   repeated failing creates leave the heap block count and the process handle count unchanged.
7. **Auto-started broker.** Started with the broker's own directory as working directory. Unless
   `CML_BROKER_ARGS` supplies them, it gets `--exit-when-idle 300000` (exits five minutes after the last agent
   left) and `--startup-timeout 60000` (exits if nobody connects within a minute). The integration tests assert
   that auto-started brokers exit by themselves; a unit test checks the command line.
8. **Module polling** happens once per flush pass instead of once per request.
9. **cml_agent.dll no longer imports shell32.** `command_line_arguments` moved into `cml_broker`
   (`broker/cml_cli`), which links shell32 itself; `cml_proc` links only advapi32. A unit test parses the PE
   import table of `cml_agent.dll` and fails on anything other than kernel32, advapi32, ntdll and
   `api-ms-win-core-*` forwarders.
10. **Deduplicated.** One request helper in `Agent` for enable/disable, one `ModuleInfo` to `ModuleEntry`
    conversion, and a shared header-only path helper `core/cml_util/include/cml/util/path.h`
    (`base_name`, `parent_directory`, `same_path`, `matches_module`) used by the agent, the broker session and
    the log sinks. This is the one file added to `core/cml_util` (outside the WP's directories).

Documented behaviour for `KNOWN_LIMITATIONS.md`: module changes are noticed with up to 500 ms delay (the
module list is refreshed before every request pass); the agent DLL is never unloaded once its create function
ran.

## Review fixes (third pass)

1. **Answers nobody collects cannot lock the table.** A request made without a request id (`request_id ==
   NULL`) keeps no answer at all. Collected-or-not answers are kept only up to 512 and the oldest are dropped
   first; `enqueue()` also evicts the oldest uncollected answers when the table (1024 + 256 reserved for
   internal re-enables) is full. Only genuinely open requests can fill it; that is back-pressure
   (CML5217) which clears as the broker answers. Test: 5000 fire-and-forget enables and 1500 uncollected ones,
   then a waited request still succeeds.
2. **A rejected request is answered, a rejected answer drops the connection.** `Received` now carries the raw
   type, whether it is a request type and the request id peeked from the first 8 payload bytes. Broker: a
   rejected Hello/ModuleList/EnableModule/DisableModule gets an error Reply (CML5201/5202/5203) for its id;
   when the id is unreadable the connection is closed; rejected events are logged and skipped. Agent: an
   undecodable Reply/Welcome closes the connection (so `fail_in_flight` runs); other rejected messages are
   skipped. Tests on both sides (the agent one against a scripted raw-pipe broker).
3. **ModuleLoaded still precedes an EnableModule for that module.** Each request gets a queue sequence
   number; a module poll records the sequence it covered; before sending a request queued after the last
   poll the agent polls again. Test: load a DLL and enable it repeatedly while another thread keeps the
   flush passes busy.
4. **accept() error paths.** After an unexpected error the listening instance is closed and a fresh one is
   created on the next accept. `ConnectionServer` has a stop event: it wakes `accept()` at once and replaces
   the retry `Sleep`; the retry path still reaps connections and evaluates the idle and startup timers.
5. **Re-enables after repeated reconnects.** Re-enable entries left from the previous session (queued or
   sent) are dropped before the new ones are queued, the table reserves room for them, and a lost
   connection no longer drops a module from the tracked set (it only did so when the broker refused the
   re-enable; found by the test). Test: 40 enabled modules, two quick reconnects: every module exactly once
   on the last connection, and a new request is still accepted.
6. **Broker working directory.** `broker_working_directory` returns the broker's directory, `C:\` for a
   drive root and nothing (inherit the host's) for a directory too long for `lpCurrentDirectory`.
   `absolutize_log_argument` makes a relative `--log` in `CML_BROKER_ARGS` absolute against the host's
   directory before launch; other relative paths in `CML_BROKER_ARGS` resolve against the broker's
   directory (documented in broker_launch.h). Unit-tested.
7. **read_growing_string** treats a result of `capacity - 1` as possibly cut (GetModuleFileNameExW) and
   grows. Tested with fetchers of both behaviours.
8. **Enable options are updated** when an already tracked module is enabled again. Tested (the last
   connection re-enables module_0 with the options of the later enable).
9. **Import-table test** maps every RVA through the section table and bounds-checks every structure and
   name against the file; an unmappable RVA, truncated table or unterminated name fails the test. PE32+
   only (x86 is out of scope).
10. **In-flight counter.** `sent_count_` is maintained wherever an entry changes state (`note_sent_locked`,
    `finish_locked`), so the window check no longer scans the table under the mutex.
