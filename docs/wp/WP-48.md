# WP-48: the agent sees every module load and unload (R-53)

Branch `wp/48-module-events`, ADR-0044 (review: high, agent). Diagnostic ranges: agent CML4720–CML4739 (four used; see "Decisions
for the orchestrator", D2), broker CML5620–CML5629 (two used). New agent message `ModuleEvents` (0x0015); the agent's wire ABI
(`Hello::agent_abi_version`) goes from 2 to 3; the C interface `CML_AGENT_ABI_VERSION` stays 2 (D1).

Status: **round 1 pushed**, waiting for the Windows matrix (the PR description has the run ids).

## The defect (R-53)

`Agent::poll_modules` compared two module-list snapshots every 500 ms. A FreeLibrary + LoadLibrary at the same base between two
polls (same base, size and path) looked like no change: the new image ran its original code, the broker kept the state of the old
instance, nothing was re-applied, nothing was reported. WP-45's re-enable path (carry, `forget_range`, re-apply) only ran for an
unload the poll happened to see.

## What was built

| Piece | Where |
|---|---|
| The loader notification callback, registered with `LdrRegisterDllNotification` (resolved from ntdll; the types are declared as MSDN documents them) at `Agent::start`, unregistered at `stop()` after the agent thread has ended. Under the loader lock it only appends to the ring: no loader call, no allocation, no lock, no log, no wait | `agent.cpp` (`on_loader_notification`, `register_module_notifications`, `unregister_module_notifications`) |
| The ring: preallocated (one heap block at start, 256 slots, each with room for a 520-unit UTF-16 path), lock-free bounded multi-producer queue (one CAS claims a slot, one release store publishes it), one consumer (the agent thread's poll). Each event that gets a slot gets the ring's next sequence number (1, 2, ...); a full ring drops the event and counts it (`lost()`) | `module_ring.h` (portable, header-only) |
| The drain and reconciliation: `track_modules` applies the drained events in order to what the broker was told (`ModuleTrackState::known`) and returns the events to report. An unload of a known base is reported, of an unknown base is redundant; a load of exactly the known entry is redundant (the session's full list had it); a load at a base that holds another module reports that one's unload first; a cut path is completed from the snapshot (same base and size). The snapshot is taken right after the drain and stays the fallback and the check: a ring that lost events (CML4721) or a path that cannot be resolved (CML4723) completes the report from the snapshot diff (a resync); a difference between the events and the snapshot is corrected only when two quiet polls in a row show the same one (CML4722), so a notification delivered before the module list shows the change, or after, never reaches the broker | `module_diff.{h,cpp}` (portable) |
| Patch images: the patch loader marks the base it is loading or freeing (`ScopedPatchImage`, an atomic the callback reads); those events are dropped, as the snapshot leaves patch images out | `loader/patch_loader.cpp`, `module_ring.h` |
| The poll: drains, snapshots, reconciles; `forget_range` (WP-45) for every unloaded image before the broker hears of it, so also for an unload followed by a load inside one poll; then one `ModuleEvents` (chunked at 1024 events / about 512 KiB) to a broker that answered with agent ABI 3, or the same events as `ModuleUnloaded` / `ModuleLoaded` to an older broker. A ring that is half full is drained at once (the agent thread wakes at least every 250 ms). The first module list of a session drops what the ring held before it (drained before the list is taken, so a change during it is reported by the next poll) | `agent.cpp` (`poll_modules`, `send_module_report`, `send_module_list`) |
| Fallback: without notifications (CML4720: not available, registration failed, or the test option `CML_TEST_NO_LOADER_NOTIFICATIONS`) the agent keeps the module-list diff of before (`poll_by_snapshot`) | `agent.cpp` |
| Wire: `ModuleEvents {flags, reason, lost, events[{kind, seq, entry}]}` (event, no id, no answer; `kModuleEventsResync` with the agent's reason id; decoder checks flags, kinds, counts against the payload); `Welcome::agent_abi_version`, an optional trailing field written only to an agent whose Hello announced 3 or more (an older agent's decoder rejects trailing bytes); `kAgentAbiSnapshots = 2`, `kAgentAbiModuleEvents = 3` | `core/cml_ipc` (`messages.{h,cpp}`) |
| Broker: `Session::on_message(message, after_step)` applies a `ModuleEvents` one event at a time and calls `after_step` after each; the connection thread publishes the session and calls `ReloadService::on_session_changed` there. So an unload and a load of the same image at the same base are two changes: the first drops the state and keeps its baseline (the carry, `live=false` because the image is gone), the second creates the new instance, which takes the carry and re-applies (WP-45's path, unchanged). A pair inside one report is logged as evidence `WP48-PAIR agent#.. pid=.. base=.. seq=a,b module=..` | `session.{h,cpp}`, `connection_server.cpp` |
| Broker: an agent of ABI 2 (or 0) gets the old Welcome (no trailing field) and the warning CML5621 in the broker log; its ModuleLoaded / ModuleUnloaded are handled as before. A resync is the warning CML5620, logged and published as a `diag` event (stage `modules`) | `session.cpp`, `connection_server.cpp`, `module_event_diag_ids.h` |

## Decisions for the orchestrator

* **D1, which ABI number goes up.** ADR-0044 says `agent_abi_version` goes up by one. The agent sent `CML_AGENT_ABI_VERSION` in
  Hello; that macro (agent/include/Chameleon_API.h, outside this package) versions the C interface between the application and
  cml_agent.dll, and ADR-0034 keeps it at 2 because a bump makes every application rebuild (the header refuses a DLL of another
  version). This package bumps the wire ABI instead: `ipc::kAgentAbiVersion = 3` in Hello (`hello.agent_abi_version` was 2 and is
  now 3); `CML_AGENT_ABI_VERSION` stays 2, so applications need not be rebuilt and an old agent DLL still loads. If the C interface
  should go to 3 as well, it is the header line and `tests/unit/agent/fake_agent_abi.cpp`, outside these directories.
* **D2, the agent range.** ADR-0044 gives the agent CML4700–CML4719, but WP-36 (ADR-0042) owns that block already (CML4700 is
  `kLoaderAddr32NbOutOfRange`). This package uses CML4720–CML4723 (the next free block, CML4720–CML4739). Renumbering is four
  constants and the TROUBLESHOOTING headings.

## Not changed / limits

* A ring overflow (more than 256 loads and unloads between two drains; it is drained every 500 ms and when half full) falls back to
  the snapshot diff for that poll, so a free + load at the same base in that moment can still be missed; it is reported (CML4721,
  CML5620), never silent.
* An agent from before WP-48 (ABI 2) keeps the 500 ms diff; the broker accepts it and says so (CML5621).
* Sequence numbers are per agent (per ring); an application has one agent, so they are per process in practice.
* The fuzz seed corpus (`tests/fuzz`, outside this package) has no ModuleEvents seed yet; the fuzz target reaches the decoder through
  its type field anyway.
