## The pipeline (plan section 3)

`reload` takes `{"pid"?, "module"?, "timeout_ms"?}`. For each enabled module (one reload at a time, a second is CML5304):

1. **sweep**: wait for the index, hash-compare the tracked files, map changed files to compilands (`compilands_for_file`). Files that map to none are warned (CML5303; clang-cl does not list code-less headers, ADR-0013).
2. **compile**: `build_env` -> `record_from_build_env` -> `compile_all` (parallel) into `<session>/<module>/obj`.
3. For each compiland, one patch: **plan** (`plan_bind` with the registry and the real `ProcessModules`), **narrowing**, **anchor** (`add_anchors`, with the plan's `associative_locator_sections` plus the `.CRT$XCU` tables of the initialisers, ADR-0028; binding object), **reserve** (`ReserveRange`, once per module; patches are placed one after another in the blocks), **link** (family mirrors the module, ADR-0027), **fix-ups** (from the patch layout, SECREL pre-applied), **load** (`LoadPatch` without fix-ups, so the stages are timed separately; relink at another base on CML4203/4205, up to `max_load_attempts`), `ApplyFixups`, `RunInitializers`, `InstallHooks`.
4. **commit**: hook table (old entry -> new entry), `SymbolRegistry` (new functions and globals become canonical, so patch 2 binds to them; hooked functions are re-pointed), baseline accepted only for files whose every compiland was patched.

Result: `{"generation","patched","hooks_installed","initializers_run","changed_files","patches":[...],"timing_ms":{sweep,compile,plan,anchor,link,load,fixups,init,hooks,total},"timing":"RELOAD-TIMING fixture=..."}`. The same line is logged at info level per patched module.

A failure after the load unloads the patch again (`ReleaseRange(UnloadPatch)`). Exception: no `HooksInstalled` in time (synchronised mode, the application did not reach `SyncPoint()`): the patch stays loaded, the hooks are remembered as installed, CML5309.

## Decisions

* **SECREL (review item 1): pre-apply, not a `Write32` wire kind.** The value (offset of the target in its old image section + addend) is known when the patch is linked and does not depend on where it lands. The broker writes it into the DLL file between link and `LoadPatch` (`preapply_write32`, every site checked against the raw data of one section before anything is written). No wire or agent change. Unit tests: `test_patch_image.cpp`.
* **Rel32 on the wire** stays "absolute target + n" (WP-08); the broker converts the planner's displacement back (`to_patch_fixups`), the agent recomputes and range-checks it.
* **Hook narrowing rule (review item 3).** A hook is dropped only if (1) the old bytes are available from the module file (old RVA and PDB size known, entry not currently redirected by an earlier patch), (2) the new code has the same length and equal bytes with every relocation site masked, and (3) every relocation resolves to the same target as in the old code: recovered old address (`S = disp + site + 4 + N - A`) equals the address the planner resolved (bound data/functions, hooked functions, `__ImageBase`); SECREL and ADDR64 sites compare against the planned values; read-only constants carried as fresh copies (string literals, tables) must be byte-equal at the old target; everything else (new symbols, fresh functions, constants holding pointers such as vtables, section symbols) keeps the hook. Rule (3) is beyond "mask the relocations": masked bytes alone miss `call a` -> `call b` and edited string literals. Reasons are logged per function at debug level (`reload: hook ...`) and unit-tested (`test_narrowing.cpp`). Unhooked functions keep running their old copy, which is the same code.
* **One patch per recompiled compiland** (not one DLL for all). Avoids duplicate thunk/definition conflicts between objects of one link; the registry is updated between patches. Cost: one link (about 30 ms) per changed TU; a reload that fails halfway leaves the earlier patches applied.
* **Staged load** (`LoadPatch`, `ApplyFixups`, `RunInitializers`, `InstallHooks`) so each stage has its own timing. Initialisers run on the agent thread, also in synchronised mode (WP-08 note; plan 4.10 says "applying thread").
* **PDB lifetime (ADR-0017).** The broker's index uses `use_cache=false`; `ModuleIndex::release_pdb()` drops the mapping, the next use maps it again; `set-option release_pdb_after_reload` releases at the end of every reload. The linker detection and the patch PDB (`read_linked_patch`) open and close their own mappings.
* **`enabled` in `status` includes the index.** Each module carries `index: {state, percent, message}`; `cmltest expect_module_enabled` waits for `ready`, so an edit can never be baked into the baseline.
* **Control pipe default name always served**, best effort (a second broker without `--control-pipe` runs without one; also when the default name cannot be resolved at all: warning, no control pipe).
* **Session directory.** A directory the user supplies (`--session-dir`, `$CML_SESSION_DIR`) is never removed; only the temporary default is, at exit, and only if no reload failed (`CML_KEEP_SESSION` keeps it too).
* **`status` and the index.** The service creates the index (state `loading`) before the registry publishes the module as enabled; an enabled module without an index is reported `pending`. `cmltest expect_module_enabled` accepts only `ready` (a missing state counts as not ready) and keeps the "index is loading" message while it waits.
* **Events never break the response path.** `on_event` only appends to a bounded queue (512; more are dropped); one writer thread per subscribed connection sends them under the same write lock as the responses, with the full 5 s timeout. A subscriber that stops reading therefore delays only its own events and never the pipeline; if a single write times out the connection is finished (a partial line may be on the pipe) and dropped after at most 5 s.
* **Hook timeout vs send failure.** Only a true timeout (CML5320) after `InstallHooks` keeps the patch loaded and records the hooks (they may still apply at the next `SyncPoint()`); a send failure or a lost agent unloads the patch like any other stage failure. A `LoadPatch` timeout sends an unload behind it (the agent handles requests in order, so it runs after a late load).
* **Linker cache** is keyed by the `linker` / `linker_path` options. `reserve_block_mb` must be at least 4 (a patch needs 4 MiB of room).
* **Generation** counts every patch that was applied, also when a later compiland of the same reload failed.

## Control commands

| cmd | args | result |
|---|---|---|
| `status` | - | + `generation`, `reload_running`, per module `index` |
| `reload` | `pid`, `module` (name or path), `timeout_ms` (default 60000) | above |
| `wait` | `for`: `idle` (default) or `index`; `timeout_ms` | `{for, modules, failed[], waited_ms}` |
| `set-option` | `name`, `value` | `{name, previous}`; options: `narrow_hooks`, `release_pdb_after_reload`, `track_system_headers`, `max_parallel_compiles`, `agent_timeout_ms`, `hooks_timeout_ms`, `reserve_block_mb`, `reserve_blocks`, `max_load_attempts`, `linker`, `linker_path`, `log_level` |
| `subscribe` | `events`: any of `diag`, `patch_applied`, `log` (default all) | `{events}` |

Events: `{"event":"diag","id","message","action","severity":"error|warning","stage","pid"}` (every pipeline failure and warning), `patch_applied`, `log`.

## Diagnostics (CML5300-5399; `pipeline_diag_ids.h`)

Stage failures keep their own id (CML14xx PDB, CML15xx/22xx compile, CML32xx plan, CML33xx link, the agent's CML42xx/43xx when it refuses a request). Own ids: 5300 no target, 5301 index not ready, 5302 timeout, 5303 changed file maps to no compiland (warning), 5304 busy, 5305 reserve failed, 5306 agent request failed/timed out, 5307 LoadPatch refused (non-diagnostic status), 5308 InstallHooks refused (same), 5309 no HooksInstalled in time, 5310 patch image cannot be prepared, 5311 bad request/option, 5312 source file unreadable (warning), 5313 module file unreadable, 5314 reserved, 5315 session directory, 5316 PDB open, 5317 agent lost, 5318 stage failed, 5319 no changes, 5320 no answer within the time limit (the agent may still act on the request; distinct from 5306 send failure / missing id). Harness: 5427 counter not monotonic, 5428 reload result mismatch.

## Not covered / limitations

* Header changes on clang-cl builds only reach compilands whose file list contains the header (ADR-0013).
* Initialisers of a patch that fail leave constructed objects behind (no undo).
* A reload that fails after patching some compilands keeps those patches.
* Multi-process reloads compile once per process.
