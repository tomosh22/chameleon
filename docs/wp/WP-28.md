## Fuzz targets

| Target | Input | What runs |
|---|---|---|
| `coff` | an `.obj` | `Object::parse`; then sections, symbols, aux decoding, `resolve_relocations`, COMDAT info, associative children, directives, `find_symbol`, `symbol_at`; `ObjectModel::from_object` + `write`, `rewrite`. |
| `pe` | a PE file | `Image::parse` as on-disk and as in-memory image; exports, imports, debug entries, CodeView, exception table (`find`), load config, TLS, `read_rva` / `read_cstring_rva` / address mapping probed at each section's edges. |
| `pdb` | a `.pdb` | written to a scratch file (cml_pdb maps files), `PdbIndex::open_pdb` twice (lazy and with `preload_all_symbols`); every query: compilands, build env, files, publics, globals, `find_proc_by_rva`, contributions, `load_all`; `is_valid_pdb_image`; inputs starting with `MZ` also go to `read_codeview_ref_from_image`. |
| `ipc` | a frame, or `[u16 type][u16 version][payload]`, or text | `decode_frame`, `parse_frame_header`, `decode_message` with the type and version taken from the input (so each of the 27 message types is reachable in both directions), `peek_request_id`, `is_request_type`; every decoded message is encoded again and must decode to the same message and re-encode to the same bytes (round trip); UTF-8 validation and sanitising. |
| `control` | a control-pipe line | the hand-written JSON parser (`json::parse`, then serialise / parse / serialise must be stable), `decode_request`, `decode_server_message`, encoders, `status_from_json`. The JSON parser is hand-written, so it is a target of its own. |

How to run one locally (clang-cl):

```
cmake -S . -B build-fuzz -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DCMAKE_CXX_COMPILER=clang-cl -DCML_FUZZ=ON
cmake --build build-fuzz --target cml_fuzz_coff
build-fuzz\bin\cml_fuzz_coff.exe -max_total_time=600 -max_len=65536 corpus-work tests\fuzz\corpus\coff
```

A reproducer is replayed with `cml_fuzz_<target> <file>` (libFuzzer build or the plain replay build). To regenerate the seeds:
`cmake --build . --target cml_fuzz_gen_seeds` and `cml_fuzz_gen_seeds tests/fuzz/corpus`.

## Failure injection

Compiled in under CMake option `CML_FAULT_INJECTION` (default ON; `CML_FAULT_INJECTION=1` is defined for every target). With
it OFF the broker does not advertise `fault-injection`, the commands do not exist, the agent answers `ArmFault` with CML4655
and every injection point is a constant `false`.

Control commands (capability `fault-injection`):

| cmd | args | result |
|---|---|---|
| `fault-stages` | - | `{stages:[...], details:[{name, side, id, where}]}` in pipeline order |
| `inject-failure` | `{stage, pid?, count?}` | `{stage, armed:true, count, side, id, processes:[pid...]}`; `{"stage":"none"}` disarms every stage in the broker and in the agents and answers `{stage:"none", armed:false}` |

`count` (default 1, at most 1000) is the number of passes of the stage that fail; the stage disarms itself afterwards. `pid`
limits the arming to one process (for a broker stage: only that process's reloads fail); without it an agent stage is armed in
every connected agent. A broker stage armed twice keeps the latest arming.

| Stage | Where it fails | Diagnostic | Notes |
|---|---|---|---|
| `pdb-load` | the broker's mapping of the PDB: it is dropped, then fails to open | CML5963 | the next reload maps it again |
| `change-detection` | the sweep that hashes the sources | CML5964 | |
| `compile` | before the compiler runs; the application's compile-error hook runs | CML5965 | |
| `bind-plan` | before `plan_bind` of the first compiland | CML5966 | |
| `reservation` (agent) | `ReserveRange` answers with the status | CML4650 | a module is reserved once, so only its first patch asks |
| `link` | before the linker runs | CML5967 | |
| `pre-apply` | before the SECREL sites are written into the DLL (the DLL is linked) | CML5968 | |
| `send-patch` | `LoadPatch` is not sent | CML5969 | |
| `patch-load` (agent) | after the DLL was mapped and placed; the real cleanup path unloads it | CML4651 | |
| `hook-install` (agent) | inside the window with the application's threads suspended, before anything is written | CML4652 | one lock-free atomic decrement, no allocation, no lock; the diagnostic text is built after the threads run again; the batch fails like any other (CML4305 and friends) and the threads are resumed |
| `post-patch-hooks` (agent) | after the hooks were installed and the application's post-patch hooks ran: the installed hooks are rolled back | CML4653 | functions that were hooked to an earlier patch are re-pointed to it, the others get their original bytes back |

Other ids: CML5960 bad request (unknown stage, bad count or pid), CML5961 no agent with that pid, CML5962 the agent refused
`ArmFault` (its own CML4654 bad stage / CML4655 not compiled in is in the message), CML5985 harness step (`inject_failure`).

Every injected failure takes the stage's normal error path: the reload is refused with the stage's diagnostic (a `diag` event as
well), a patch that was already loaded is unloaded, nothing is hooked, and the application keeps running its previous code. The
reload that follows without injection applies the same edit.

## Scenario

`inject_stages` (fixture `inject`, `compute_value()` returns one more than before for each stage, edits in `edits/stacked/`)
runs, for each of the eleven stages, edit - `inject_failure` - `reload` expecting the stage's id - `expect_diag` of that id -
`expect_stdout` of the previous value - clean `reload` - `expect_stdout` of the new value; then a disarm check
(`inject_failure link`, `none`, reload succeeds) and `expect_monotonic calls`. The reservation goes first because a module is
reserved once. It runs in every cell under `--require-all-capabilities`.

## Tests

* `unit.ipc`: ArmFault wire format, stage table consistency (`test_ipc_fault.cpp`).
* `unit.agent`: the counters (including a concurrent consumer test) and the `ArmFault` handler (`test_fault.cpp`).
* `unit.broker_core` (`test_reload.cpp`): each broker stage through the whole pipeline with the scripted agent (id, nothing sent
  to the agent that should not be, hook table and generation untouched, next reload succeeds), count, disarm, pid, agent

* `unit.harness`: the step and the checked-in scenario (every stage once, each expects its own id, edits exist).
* `fuzz.replay.<target>` x5 in every cell.
