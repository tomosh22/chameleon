# WP-01: Repository skeleton and CI

## What was built

- Top-level `CMakeLists.txt` (C++20, no extensions) plus `cmake/CmlToolchain.cmake`,
  `CmlWarnings.cmake`, `CmlTargets.cmake`. Configuration fails with a clear message on non-Windows
  or non-x64 hosts unless `-DCML_ALLOW_NON_WINDOWS=ON` (portable syntax checking only).
- Warnings: `cml_apply_warnings(t)` gives `/W4 /WX /permissive- /utf-8` (cl, plus `/Zc:__cplusplus
  /external:W0`) and the same `/W4 /WX` set for clang-cl with only `-Wno-unused-command-line-argument`
  relaxed. Vendored code uses `cml_apply_relaxed_warnings` (never `/WX`). GNU-style hosts get
  `-Wall -Wextra -Wpedantic -Werror` (only reachable with `CML_ALLOW_NON_WINDOWS`).
- Target styles: `cml_target_core_style` (no exceptions via `/EHs-c-` and `_HAS_EXCEPTIONS=0`, no RTTI),
  `cml_target_agent_style` (core style plus explicit static CRT), `cml_target_exceptions_allowed`
  (tests, GUI, third-party), `cml_target_fixture_style` (RelWithDebInfo `/Ob0`; not exercised yet,
  no fixtures exist), and `cml_add_core_library`.
- Libraries: `cml_util` (real `cml::Diag`, `cml::Result<T>` / `Result<void>`, `CML_LOG`, `cml::hash64`
  over XXH3, `cml::fail_fast`), and trivial `cml_coff`, `cml_pe`, `cml_ipc`, `cml_proc`,
  `cml_toolchain`, `cml_watch`; `cml_pdb` wraps raw_pdb's `ValidateFile`. `agent/` builds
  `cml_agent.dll` exporting `cml_agent_abi_version()` with `agent/include/Chameleon_API.h`.
  `broker/cml_core` (static, version string from the CMake project version, currently 0.1.0),
  `broker/cml_cli` (`cml_broker.exe --version`, `--help`, exit 2 on anything else),
  `broker/cml_gui` (only with `CML_BUILD_GUI=ON`; links vendored ImGui, no UI code).
  `integrations/*`, `tests/fixtures`, `tests/harness` are README-only placeholders;
  `tests/CMakeLists.txt` adds `fixtures` and `harness` automatically once they have a CMakeLists.
- `third_party/` vendored and documented in `third_party/README.md` (versions, licences, trimmed content).
- Tests: one doctest executable per library (`cml_test_<name>`, ctest `unit.<name>`), sharing
  `tests/unit/doctest_main.cpp`. Two more ctests run `cml_broker` through
  `tests/cmake/run_and_check.cmake` (`broker.version`: exit 0 and exact `cml_broker 0.1.0`;
  `broker.unknown_option_fails`: exit 2).
- CI: `.github/workflows/ci.yml`, 8-cell matrix (windows-2022/2025 x msvc/clang-cl x
  Debug/RelWithDebInfo), Ninja, `ilammy/msvc-dev-cmd` for the x64 environment, `fail-fast: false`.
  Steps: toolchain versions, configure, build, `ctest --output-junit`, `cml_broker --version`,
  upload logs always. Built with `-DCML_BUILD_GUI=ON` so ImGui and the D3D11 backend are
  compiled in every cell. One extra job (`vs-generator`) configures, builds and tests with the
  "Visual Studio 17 2022" generator on windows-2022 Debug.

## How to run

See `README.md`. Locally on Windows (x64 developer prompt):
`cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug && cmake --build build && ctest --test-dir build --output-on-failure`.
VS generator: `cmake -S . -B build-vs -G "Visual Studio 17 2022" -A x64`.
On Linux, only for syntax checking: add `-DCML_ALLOW_NON_WINDOWS=ON`.

## Decisions

- Whole project uses the static CRT (`MultiThreaded[Debug]`), not only `agent/`: static libs that
  link into the agent must share its runtime or the link fails with LNK2038.
- `/EHsc` is stripped from `CMAKE_CXX_FLAGS` and chosen per target to avoid conflicting `/EH` switches.
- Core style also disables RTTI (`/GR-`) because core libs link into the agent.
- raw_pdb is BSD-2-Clause, not MIT as the plan says (permissive; recorded in `third_party/README.md`).
- Only the CXX language is enabled (no C sources), so CI does not pass `CMAKE_C_COMPILER`.

## What was learned

- The first CI run (commit 93bc6f0) was green in all 8 cells plus the VS-generator job with no
  fixes needed. Before pushing, the portable parts were compiled with clang on Linux using
  `-Wall -Wextra -Wpedantic -Werror` under `CML_ALLOW_NON_WINDOWS=ON` (all 12 ctests passed
  there); that caught typos but proves nothing about MSVC, which was verified only in CI.
- The `windows-2025` image ships Visual Studio 18 (MSVC 14.51, Windows SDK 10.0.26100) as the
  default developer environment, not VS 2022. `ilammy/msvc-dev-cmd` picks it up. So the
  windows-2025 cells test a newer MSVC than the windows-2022 cells; the `Visual Studio 17 2022`
  generator is only exercised on windows-2022.
- `C:\Program Files\LLVM\bin\clang-cl.exe` exists on both images and is used with MSVC's
  `link.exe`; the exact versions are printed to `ci-logs/toolchain.txt` (uploaded as an artifact).
- A push to a `wp/**` branch with an open PR triggers both the `push` and `pull_request` runs,
  so each commit builds twice.
- GitHub warns that `actions/checkout@v4`, `upload-artifact@v4` and `msvc-dev-cmd@v1` run on a
  deprecated Node 20 runtime; harmless today, bump the action versions when v5 variants exist.
