## How the checks decide

* **Image**: `cml_pe` loads the module; PE32 (CML1303) or a machine other than AMD64 is CML1106 (FAIL).
* **PDB**: `PdbIndex::open_for_pe` (use_cache off, ADR-0017); a PDB that is missing or of another build is a FAIL finding with the
  reader's id (CML1410 / CML1411), and the remaining checks, which need the PDB, are not evaluated.
* **CML1101 (full PDB)**: FAIL when the `* Linker *` compiland's recorded command line has `/DEBUG:FASTLINK`, or when none of up to 16
  sampled compilands that contributed code lists a function symbol (a FASTLINK or stripped PDB). The second rule is a heuristic, and
  it never fires when no compiland could be sampled.
* **Per compiland** (source compilands only: not library members, imports, `* Linker *`, MASM/CVTRES): the recorded command from
  `S_ENVBLOCK` or `S_BUILDINFO` (CML1102), `cml_toolchain::detect_compiland_flags` for `/GL`, `/guard:cf`, `/Gy` (with the recorded `.obj`
  when it is still on disk, up to 8 MiB each and 128 MiB in all), the S_COMPILE3 managed bits (CML1504), and whether the command allows
  inlining (optimised and no `/Ob0` / `-fno-inline`; a command with no `/O` option is `/Od`). At most 4000 compilands are examined.
* **`/guard:cf` for the module** also uses `detect_module_guard_cf` (DllCharacteristics plus a non-empty function table, never GuardFlags alone: ADR-0015).
* **CML1601**: up to 64 function publics of source compilands, evenly spread; PASS when all of them have six `CC`/`90` bytes before the entry.
  A WARN when some do not, or when none could be sampled.
* **CML1602**: from the linker command line in the `* Linker *` compiland (`/OPT:` lists, last wins; with `/DEBUG` the defaults are NOREF and NOICF).
  When no linker command line is recorded the check is a WARN "cannot be determined", never a FAIL.

## Deferred, with reasons

* **CML3103 (layout of a type changed)**: it needs the UDT layouts of the old PDB and of the patch (TPI: member lists, sizes, vtable
  slots), and `cml_pdb` does not read type records (WP-04 left them out). Building a TPI reader and the comparison is a package of its own; the
  planner has no type access either (ADR-0029). The id stays reserved and `docs/KNOWN_LIMITATIONS.md` says so.
* **CML2300-2399**: no compile-time check needed an id. The compile-time conditions of plan 1 and 4.2 already have ids in the ranges
  `cml_toolchain` owns (CML1504, CML2102, CML2210), or are module properties (CML16xx).
* **Enable-time negative scenarios through cmltest**: the harness builds exactly `fixture_<name>` per scenario, so one scenario per bad build
  would need one fixture directory per bad build. The `check.*` ctest tests assert the exit code and id on the real bad builds, and the
  enable-time path is covered by unit tests (the same function runs in both places). The only cmltest scenario is `optimised`.
* **CML2101** (PCH header): WP-15's.
