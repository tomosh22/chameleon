**Why the host is changed at all.** A plugin can only enable itself through the agent the host created (a second agent
in one process would be a second "process" for the broker). Godot has no hook for that, so the host gets two exports,
`cml_corpus_host_agent()` and `cml_corpus_host_marker()`, appended to the corpus support file of this cell's copy of the
checkout. That is the host's part of a plugin architecture that uses Chameleon; Godot's patch, its build script and the
cache key are unchanged, and the cell `godot / msvc` never sees the change (this cell restores the cache and does not
save it; scons recompiles one file and relinks the editor here).

**Why `--script` and not `--editor`.** In the editor (`Engine::is_editor_hint()`), Godot loads a GDExtension from a
temporary copy of the DLL with a renamed PDB, and loads it when its filesystem scan finds it, which the driver cannot time.
Running the project's script with the editor binary loads the DLL itself, exactly when the driver says so.

### Driver changes in `run_corpus.ps1` (generic needs)

* `ValidateSet` gains `godot-gdextension`; `project.json` may name `src_dir` (a checkout shared with another project, here
  `src-godot`, so the cached Godot tree is reused).
* `build.ps1` may list further modules in `$script:ExtraModules`; each gets `check:<file>` and `decode:<file>` (the same
  checks as the executable, with its own `min_functions`).
* Edit kinds (an entry of `edits` without `kind` behaves as before):
  * `signal`: writes `write.text` to `write.file` (the application polls it), then waits for every `expect` regex, for
    `expect_grows` (a marker whose count rises above the newest CORPUS line before the step), and for `wait_module` (a module
    of the process, by path regex, enabled with its index `ready`, from `status`); `absent_before` fails the step when such a
    module is already listed;
  * `check`: the same without writing;
  * `restart`: hot-restart through `restart {pid, timeout_ms, registration_timeout_ms}`; asserts `expect_diag` (response
    or diag events), `expect_not_enabled` (path regex in `not_enabled`), `expect_reapplied` (no `reapply_error`,
    `reapplied_files` and `patched` at least 1); follows the new pid and waits for its AGENT and CORPUS lines.
* On failure the tail of `app.stdout.txt` is printed too (main.gd writes its load/unload results there).

## How to run

`pwsh tests/corpus/run_corpus.ps1 -Project godot-gdextension -Compiler msvc -ChameleonBin <build>/bin -WorkDir <dir>`
(Windows, from an x64 Native Tools prompt; `python` and `git` on PATH). CI: `corpus` on a pull request, or
`workflow_dispatch` with `only=godot-gdextension`.
