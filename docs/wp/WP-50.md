# WP-50: first-reload cost and hot-restart time (R-47, R-55)

One branch (`wp/50-reload-cost`), one PR. ADR-0044, section WP-50: measure before changing anything, then fix what the
measurement shows, within the broker, the agent's timing and logging, and caching. Hook-installation semantics and the
restart protocol are not changed.

**State: round 1 (measurement only).** Nothing that decides what is hooked, how, or how a restart proceeds was changed.
The numbers of the branch's own CI runs and the proposed fixes are in the pull request until the orchestrator rules; this
file is completed with them in round 2.

## What was built (round 1)

| Piece | File | Notes |
|---|---|---|
| Thread-call timing | `agent/src/hook/thread_set.{h,cpp}` | `ThreadSet::Timing`: QueryPerformanceCounter ticks around NtGetNextThread (+ GetThreadId, closing the walk's handles), SuspendThread, GetThreadContext and ResumeThread (+ closing the handles). One counter read on each side of each call; nothing allocated, no lock, so it is window-safe. The last-error values are now read before the second counter read. |
| Batch timing | `agent/src/hook/installer.{h,cpp}`, `agent/src/hook/hook_timing.h` | `BatchResult::timing` (`BatchTiming`, microseconds): the mutex wait, planning (and the ReadProcessMemory / VirtualQuery calls in it), VirtualProtect, the stop (enumeration, suspension, contexts), the RIP check and byte verification, the writes (total and slowest single hook), the offender steps, resuming, the waits between attempts, VirtualProtect back, the registry; job counts by kind and the pages made writable. ## What was known before this package (from existing logs)

### R-47, the first reload in the WP-39 benchmark (run 45666144233, job 139388698443, `pdb-benchmark`, main d860925)

```
RELOAD-TIMING fixture=bench_project sweep_ms=9.8 compile_ms=355.0 plan_ms=329.2 anchor_ms=6.1 link_ms=73.7 load_ms=0.5 fixups_ms=1.3 init_ms=0.0 hooks_ms=395.5 total_ms=1177.5
RELOAD-TIMING fixture=bench_project sweep_ms=10.5 compile_ms=351.5 plan_ms=34.9 anchor_ms=6.2 link_ms=48.4 load_ms=0.5 fixups_ms=1.3 init_ms=0.0 hooks_ms=2.4 total_ms=461.2
WP39-RELOAD pdb_mib=546.1 reloads=5 total_minus_compile_median_ms=110.2 max_ms=822.5 ...
```

The first reload costs 712 ms more than the median (822.5 against 110.2 ms of `total - compile`); the acceptance asks
for at most 300 ms. Of the 712 ms: plan +294 ms (WP-39: the module file, 297 MiB, read into `Run::module_image`), hooks
+393 ms (unexplained), link +25 ms (linker detection, the rest WP-39b removed).

### R-55, the Godot hot-restart (run 45690362934, job 139475939418, cell `godot-gdextension / msvc`)

`MATRIX ... restart:hot-restart-lazy-plugin: PASS restart 169159 ms`. From that run's `broker.log` (artifact
`corpus-godot-gdextension-msvc`), times relative to the broker's start:

| Stage | from | to | ms |
|---|---|---|---|
| prepare (no pre-restart hooks) | 181535 | 181537 | 2 |
| terminate | 181538 | 181552 (started) | 14 |
| relaunch to registration | 181552 | 181849 | 297 |
| index: PDB opened (the module was enabled by the application at 181829) | 181829 | 182105 | 276 |
| index: build-requirement checks | 182105 | 182780 | 675 |
| **index: file lists and include scan of 2607 compilands, 70480 paths read for 3389 headers** | 182782 | 346121 | **163339** |
| index: source hashes, 5858 files | 346122 | 348392 | 2271 |
| re-apply (one reload) | 348394 | 350694 | 2300 |
| total | | | 169159 |

The enable at the session's start shows the same: 171.3 s, of which 163.5 s include scan (1393 to 164912 ms). The include
scan is 96.6 % of the hot-restart. The round-1 lines say whether the scan is the file system (`scan_read_ms`, and
`scan_missing` of the 70480 paths) or the walk itself.
