# WP-06: cml_coff writer, anchors and binding object

### Writer and byte-identical round trip

`from_object()` + `write()` reproduces every object the reader accepts **byte for byte**, regular and bigobj. Verified on the synthetic objects (incl. 70000-section bigobj, 70000 extended relocations) and on every fixture object in every CI cell: `basic` (`main`, `logic`, `extras`), `extras.cpp` compiled `/Od`, and `bigobj` (66000 functions under clang-cl, 200 under cl), through the WP-02 `writer_roundtrip_hook()` (installed from `test_coff_writer.cpp`; `test_coff_roundtrip.cpp` now also covers `bigobj_objs`).

Why identity is achievable without knowing the compilers' layout rules: the model keeps the raw file header and optional header (only section count, symbol pointer and symbol count are patched), the raw 8-byte name fields, every symbol as raw record + raw aux bytes, the string table as raw bytes (new strings are only appended), the ORDER of the file regions (section data, relocation tables, line numbers, symbol table + string table) and the padding bytes between them and after the last one. A hand-made test object with an optional header, padding, line numbers before the relocation table, a bss with a bogus raw pointer and trailing bytes also round trips. Where it cannot: regions that overlap each other or the headers are refused with CML3304 (never seen in a compiler object).

No exceptions; sizes are checked in 64 bits (CML3300), regular objects are limited to 65279 sections (CML3301), symbol section numbers, aux sizes (CML3302) and relocation symbol indices (CML3303) are validated on write. A model grown past 65534 relocations in one section gets the `LNK_NRELOC_OVFL` record automatically. A fresh model always carries the 4-byte string-table size field (LLVM and link.exe expect it); a parsed object that lacked one keeps lacking it until a string is added.

### Anchors (plan 4.6)

`add_anchors()` appends one symbol `__cml_anchor_<n>` (`n` = 1-based section index, value 0, type 0, no aux) per anchorable section, after the last existing record (aux records included). Nothing is reordered or renumbered, so all relocation, weak-external-tag and section-association indices stay valid; because anchors are last, the COMDAT leader (first symbol after the section definition) cannot be displaced. Verified by comparing before/after with the reader: sections, relocation tables and data identical, old symbol table an exact prefix of the new one, `comdat()` (selection, definition symbol, leader, associated section) unchanged.

Skip rule (`is_anchorable`): sections with `LNK_INFO`, `LNK_REMOVE` or `MEM_DISCARDABLE` (`.drectve`, `.chks64`, `.debug$S/T/F/P`, clang `.llvm_addrsig`), and names starting `.debug` or `.llvm_`. Everything else is anchored, including empty sections, `.bss`, `.CRT$*`, `.pdata`/`.xdata`, COMDAT and associative sections.

Options (`AnchorOptions`): default is the plan's form, STATIC. `external` makes them EXTERNAL and needs a unique `tag` (`__cml_anchor_<tag>_<n>`); `comdat_static` keeps COMDAT anchors static in external mode. Both exist because of the evidence below.

### Binding object (plan 4.5)

One regular x64 object: `.text` (16-byte aligned, CODE|EXECUTE|READ) and `.data` (8-byte aligned, READ|WRITE), plus static section symbols.

- Function: a **16-byte thunk** `FF 25 <rel32>` (`jmp qword ptr [rip+rel32]`, 6 bytes) + 10 bytes `0xCC`, symbol exactly `<name>` (EXTERNAL, DTYPE_FUNCTION), with one `IMAGE_REL_AMD64_REL32` at offset +2 against the slot, and an **8-byte zero slot** in `.data`, EXTERNAL symbol `__cml_slot_<name>`.
- Data: 8-byte zero placeholder in `.data`, EXTERNAL symbol exactly `<name>`.
- Layout decision: the plan says "14-byte thunk". `FF 25 rel32` is 6 bytes; 14 bytes is the inline-target form (`FF 25 00000000` + 8-byte target) which has no separate slot. The plan's retargeter writes slots, so the separate slot form is used and the thunk is padded to 16 so every thunk starts on a 16-byte boundary. Slots are 8-byte aligned (one atomic qword store).
- No `.pdata`/`.xdata`: the thunk does not push, allocate or touch the stack, so it is a leaf function for the x64 unwinder (return address at `[rsp]`); the target brings its own unwind info.
- Slots are visible as publics in the patch PDB (EXTERNAL symbols): verified with `cml_pdb` on every link below.
- `__ImageBase` is refused (CML3310, the linker provides it). Duplicates and slot-name collisions are CML3311.

## How to run

`ctest --test-dir build -R "unit\.coff"` (`unit.coff`: writer, anchors, binding structure, thunk decoding, round trips; `unit.coff_link`: link.exe and lld-link, about 2 minutes). `unit.coff_link` needs both linkers and fails when one is missing; for a local run with one linker set `CML_TEST_LINKERS=lld-link`. It writes `<build>/test_work/coff_link/evidence.txt`, which CI prints in the step "WP-06 link evidence" (also in `ci-logs/wp06-evidence.txt`).

## Acceptance evidence (CI run 40163339688, head 28b362a, all 10 jobs green)

`unit.coff_link` links each set with `<linker> /nologo /DLL /NOENTRY /NODEFAULTLIB /MACHINE:X64 /DEBUG:FULL /INCREMENTAL:NO /OPT:NOREF /OPT:NOICF /FUNCTIONPADMIN /FIXED /DYNAMICBASE:NO /BASE:0x180000000 /BREPRO /PDB /OUT /IGNORE:4001,4254,4281 <objs> binding.obj`. Sets: `logic`, `extras`, `main`, `main+logic+extras`, `extras` at `/Od`, `bigobj` (bigobj_funcs + main). Each set is linked three ways per linker (unanchored; static anchors; external anchors), 3 x 2 x 6 = 36 links per cell.

1. **binding.obj is accepted by both linkers with every real fixture object**, no `/FORCE:UNRESOLVED`, no unresolved symbols (bind lists computed from the objects' undefined externals: e.g. cl Debug `main.obj` 44 symbols of which 31 functions, `extras.obj` 12/9). In each linked image every thunk was read back: bytes `FF 25`, rel32 lands exactly on its `__cml_slot_<name>`, the slot is in a writable section and is a public in the PDB; function thunks are flagged as function publics, data placeholders are publics.
2. **Anchored vs unanchored, both linkers, both anchor kinds, all sets, in the two cells whose logs were read in full (windows-2022 msvc Debug = cl objects, windows-2022 clang-cl Debug; the other six cells passed the same assertions): section table (names, RVAs, sizes, characteristics) identical and all code sections byte-identical.** With equal-length PDB paths and `/Brepro`, the only bytes that differ in the whole image are the PE timestamp/checksum and the debug directory with its RSDS record (GUID, PDB path); `outside_debug_info_bytes_differing=0` in all 48 inspected comparisons. Anchors do not perturb the output under either linker.
3. **Where anchors show up in the PDB** (this is the finding):
   - **STATIC anchors (the plan's form): nowhere.** `in_pdb_publics=0`, `in_pdb_module_symbols=0` for every set, under link.exe and lld-link. Neither linker publishes non-external COFF symbols to the PDB, and neither copies them into the module (compiland) symbol streams. So static anchors are harmless but the PDB cannot tell where a section landed through them.
   - **EXTERNAL anchors: in the PDB publics (S_PUB32) with their RVA**, under both linkers (every anchor of every single-object set, e.g. cl `extras.obj` 96/96, `main.obj` 735/735, 200-function bigobj 623 in a combined link). Limits found: (a) an external symbol inside a COMDAT that the linker drops as a duplicate is missing from the publics under link.exe and makes **lld-link fail with "undefined symbol"** (first CI run: `main+logic+extras` with external COMDAT anchors); hence `comdat_static`, used by the test for every multi-object set (then the COMDAT anchors are static and invisible, the others are publics). (b) names need a per-object tag.
   - **Section contributions (DBI), no anchors needed:** evaluated by comparing, for every published external anchor, the PDB contribution at the anchor's RVA (module, start, size). lld-link: **exact for every section** (e.g. 735/735, 96/96, 101/101, bigobj clang-cl 198008/198008 in the local run). link.exe: exact for everything except `.pdata` (link.exe builds `.pdata` itself and records no per-object contribution for it; every sampled mismatch was a `.pdata` COMDAT, e.g. 526/735, 74/96); the CI evidence lines of the final head also print the figure without `.pdata`. A contribution identifies module, RVA and size, not the object's section index, so matching to object sections needs the object's section order (sections that occupy space, in order) or an anchor.
   - Recommendation for WP-09: keep static anchors (zero risk, but not PDB-visible), or use `external` + `tag` for non-COMDAT sections and rely on COMDAT leaders (already publics) and PDB section contributions for the rest. The risk-table alternative (section contributions from the PDB) works well enough to be the primary mechanism for link.exe and lld-link; anchors only add certainty for non-COMDAT sections. This is the decision for the orchestrator; both are implemented and tested.

CI also verified: round trip identity of all fixture objects per cell (`unit.coff`), the VS-generator job (link.exe found through CMake, no developer environment), and `pdb-benchmark`.

## Diagnostics (CML3300..3349)

| id | meaning | what to do |
|---|---|---|
| CML3300 | a count, offset or size does not fit its COFF field (string table, symbol table, object > 4 GiB) | split the module into smaller objects |
| CML3301 | regular object would have more than 65279 sections | write /bigobj |
| CML3302 | symbol has a bad section number or aux data | fix the symbol |
| CML3303 | relocation names a symbol index that does not exist | never remove/reorder symbols |
| CML3304 | object cannot be reproduced losslessly (overlapping regions, line numbers out of range, wrong header size) | rebuild with the compiler |
| CML3305 | section name empty/NUL/not encodable | rename |
| CML3306 | object already has `__cml_anchor_*` symbols | anchor the compiler's object |
| CML3307 | bad anchor options (external without tag, tag characters) | fix options |
| CML3310 | bind symbol name empty, NUL, or linker-provided (`__ImageBase`) | drop it from the bind list |
| CML3311 | duplicate bind symbol or slot-name collision | list once |
| CML3312 | binding object would exceed COFF limits | bind fewer symbols per patch |

None is a by-design limitation for `KNOWN_LIMITATIONS.md` except possibly CML3304 and CML3301 (not seen in practice).

## What was learned

- LLVM's `llvm-readobj` silently shows no symbols when the string-table size field is missing; link.exe/lld-link tolerance for that was not tested, so a fresh model always writes the field.
- clang-cl does not type undefined function symbols as functions (type 0), cl does (0x20); bind kinds therefore must come from the PDB/relocation context (the test classifies by call/jmp rel32 and ADDR32NB references).
- Separate PDB paths of different length change `.rdata` layout (the RSDS path is in the image): compare link outputs from directories with equal-length names.
- link.exe, as lld-link, accepts static and external anchors in associative `.pdata`/`.xdata` COMDATs.
- Test-only: `WIN32_LEAN_AND_MEAN`/`NOMINMAX` are already defined on the test command line (C4005 under /WX), so the link test guards its own definitions.

## Deferred

- Matching PDB section contributions to object section indices (for sections without an external anchor) is left to the bind planner / WP-09; the evidence shows the contribution table carries the needed addresses.
- Converting a regular model to bigobj automatically (CML3301 asks the caller to choose).
- Anchoring the binding object itself (not needed: its symbols are publics).
- ARM64/x86 relocation handling in the writer (relocations are written raw; the binding generator is x64 only).
