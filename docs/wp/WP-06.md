# WP-06: cml_coff writer, anchors and binding object

## What was built

All in `core/cml_coff` (no reader behaviour changed, no reader accessor added).

| Header | Content |
|---|---|
| `cml/coff/writer.h` | `ObjectModel` (editable copy of a parsed object), `ObjectModel::from_object()`, `write()`, `rewrite()`, `make_empty()`, `add_string/add_symbol/add_section`, `make_section_definition_aux()` |

### Writer and byte-identical round trip

`from_object()` + `write()` reproduces every object the reader accepts **byte for byte**, regular and bigobj. Verified on the synthetic objects (incl. 70000-section bigobj, 70000 extended relocations) and on every fixture object in every CI cell: `basic` (`main`, `logic`, `extras`), `extras.cpp` compiled `/Od`, and `bigobj` (66000 functions under clang-cl, 200 under cl), through the WP-02 `writer_roundtrip_hook()` (installed from `test_coff_writer.cpp`; `test_coff_roundtrip.cpp` now also covers `bigobj_objs`).

Why identity is achievable without knowing the compilers' layout rules: the model keeps the raw file header and optional header (only section count, symbol pointer and symbol count are patched), the raw 8-byte name fields, every symbol as raw record + raw aux bytes, the string table as raw bytes (new strings are only appended), the ORDER of the file regions (section data, relocation tables, line numbers, symbol table + string table) and the padding bytes between them and after the last one. A hand-made test object with an optional header, padding, line numbers before the relocation table, a bss with a bogus raw pointer and trailing bytes also round trips. Where it cannot: regions that overlap each other or the headers are refused with CML3304 (never seen in a compiler object).

Line numbers are never changed silently: a header with a count but no table (or the reverse) is CML3304 on input, and so is a model with a count/pointer but no table on output. No exceptions; sizes are checked in 64 bits (CML3300), regular objects are limited to 65279 sections (CML3301), symbol section numbers, aux sizes (CML3302) and relocation symbol indices (CML3303) are validated on write. A model grown past 65534 relocations in one section gets the `LNK_NRELOC_OVFL` record automatically. A fresh model always carries the 4-byte string-table size field (LLVM and link.exe expect it); a parsed object that lacked one keeps lacking it until a string is added.

### Section locators and anchors (plan 4.6, ADR-0020)

`add_anchors()` gives every section a `SectionLocator {section_index, kind, reason, symbol_name, symbol_index, offset}` (returned per section, element i = section i + 1). The PDB publishes only EXTERNAL symbols, so:

| section | locator |
|---|---|
| non-COMDAT, linked into the image | **Anchor**: new EXTERNAL symbol `__cml_anchor_<tag>_<n>` (n = section index), value 0, appended |
| COMDAT with an external leader (if the first symbol after the definition is not external: any other external symbol defined in the section) | **ComdatLeader**: no new symbol; the leader is already a public; section start = leader RVA - `offset` (that symbol's value) |
| associative COMDAT (.pdata/.xdata children) | none (`Associative`): never retargeted to old data |
| COMDAT without a symbol after its definition | **Anchor** (reason `NoLeader`) |
| COMDAT whose leader is static (static inline function, static data) | **Anchor** (reason `StaticLeader`): static symbols are not in the PDB |
| .drectve, .debug*, LNK_INFO/LNK_REMOVE/DISCARDABLE, .llvm_* | none (`NotLinked`) |

Only `Associative` and `NotLinked` sections have no locator; a caller that needs one calls `require_locator()` and gets CML3309 naming the reason, never a silent gap. Why no anchors inside COMDATs: an external symbol in a COMDAT that the linker discards as a duplicate makes lld-link fail with "undefined symbol" (first CI run, `main+logic+extras`); with the leader as locator both copies resolve to the one kept section. Leaders are not always external (static functions and data in COMDATs are common: cl 2-14 per object), so those COMDATs get an external anchor too. This is safe because the failure above only happens when a COMDAT is DISCARDED as a duplicate, and cross-object folding is keyed by the external leader name: a COMDAT with a static or missing leader is never selected against another object's copy, and the only other discard path, `/OPT:REF`, is off (`/OPT:NOREF`). Proven by the synthetic pair, whose static-leader COMDATs have the SAME static name `static_fn` in both objects: both anchors resolve under both linkers.

**Precondition: the patch is linked with `/OPT:NOREF /OPT:NOICF`.** `/OPT:REF` drops unreferenced COMDATs and their leader publics (the `shared_comdat` test links with `/OPT:REF` and shows the unreferenced leader `unique_a` gone from the PDB under both linkers), `/OPT:ICF` can give two sections one address. WP-09 enforces the flags.

Guarantees: `add_anchors()` is transactional (on any failure the model and `used_tags` are unchanged; the string-table limit is configurable to test this) and does no tag work at all when no section needs an anchor; the leader / section-definition rule lives in one header (`section_symbols.h`) shared with the reader; symbols are only appended, after the last record (aux included): no relocation index, weak-external tag or section association changes, and the COMDAT leader rule holds by construction. Sections, relocations and data are untouched. Verified against the reader (old symbol table an exact prefix of the new one, `comdat()` unchanged).

Tags: `__cml_anchor_<tag>_<n>` must not collide between objects of one link. The default tag is 16 hex digits of a 64-bit hash (`hash64`, xxh3) of the complete object file: `AnchorOptions::object_bytes` takes the compiler's original bytes, otherwise the model is serialised once (for a parsed, unmodified object the same bytes); the caller can pass its own (`AnchorOptions::tag`, e.g. the compiland index). `AnchorOptions::used_tags` is a set shared by the objects of a link: a repeated tag is refused with CML3308, and `check_unique_tags()` checks a list. Identical objects therefore cannot be linked twice. STATIC anchors do not exist any more except as a test probe.

### Binding object (plan 4.5)

One regular x64 object: `.text` (16-byte aligned, CODE|EXECUTE|READ) and `.data` (8-byte aligned, READ|WRITE), plus static section symbols.

- Function: a **16-byte thunk** `FF 25 <rel32>` (`jmp qword ptr [rip+rel32]`, 6 bytes) + 10 bytes `0xCC`, symbol exactly `<name>` (EXTERNAL, DTYPE_FUNCTION), with one `IMAGE_REL_AMD64_REL32` at offset +2 against the slot, and an **8-byte zero slot** in `.data`, EXTERNAL symbol `__cml_slot_<name>`.
- Data: 8-byte zero placeholder in `.data`, EXTERNAL symbol exactly `<name>`.
- Layout decision: the plan says "14-byte thunk". `FF 25 rel32` is 6 bytes; 14 bytes is the inline-target form (`FF 25 00000000` + 8-byte target) which has no separate slot. The plan's retargeter writes slots, so the separate slot form is used and the thunk is padded to 16 so every thunk starts on a 16-byte boundary. Slots are 8-byte aligned (one atomic qword store).
- No `.pdata`/`.xdata`: the thunk does not push, allocate or touch the stack, so it is a leaf function for the x64 unwinder (return address at `[rsp]`); the target brings its own unwind info.
- Slots are visible as publics in the patch PDB (EXTERNAL symbols): verified with `cml_pdb` on every link below.
- `__ImageBase` is refused (CML3310, the linker provides it). Duplicates and slot-name collisions are CML3311.

## Diagnostics (CML3300..3349)

| id | meaning | what to do |
|---|---|---|
| CML3300 | a count, offset or size does not fit its COFF field (string table, symbol table, object > 4 GiB) | split the module into smaller objects |
| CML3301 | regular object would have more than 65279 sections | write /bigobj |
| CML3302 | symbol has a bad section number or aux data | fix the symbol |
| CML3303 | relocation names a symbol index that does not exist | never remove/reorder symbols |
| CML3304 | object cannot be reproduced losslessly (overlapping regions, line numbers out of range, wrong header size) | rebuild with the compiler |
| CML3305 | section name empty/NUL/not encodable | rename |
| CML3306 | object already has `__cml_anchor_*` symbols | anchor the compiler's object |
| CML3307 | anchor tag contains characters other than letters, digits, '_' | fix the tag |
| CML3308 | two objects of one link got the same anchor tag | pass distinct tags (e.g. the compiland index) |
| CML3309 | a section without locator (associative or not linked) was asked for one | locate it through its COMDAT parent or the PDB section contributions |
| CML3310 | bind symbol name empty, NUL, or linker-provided (`__ImageBase`) | drop it from the bind list |
| CML3311 | duplicate bind symbol or slot-name collision | list once |
| CML3312 | binding object would exceed COFF limits | bind fewer symbols per patch |

None is a by-design limitation for `KNOWN_LIMITATIONS.md` except possibly CML3304 and CML3301 (not seen in practice).

## What was learned

- LLVM's `llvm-readobj` silently shows no symbols when the string-table size field is missing; link.exe/lld-link tolerance for that was not tested, so a fresh model always writes the field.
- clang-cl does not type undefined function symbols as functions (type 0), cl does (0x20); bind kinds therefore must come from the PDB/relocation context (the test classifies by call/jmp rel32 and ADDR32NB references).
- Separate PDB paths of different length change `.rdata` layout (the RSDS path is in the image): compare link outputs from directories with equal-length names.
- link.exe, as lld-link, accepts static and external anchors in associative `.pdata`/`.xdata` COMDATs.
- Test-only: `WIN32_LEAN_AND_MEAN`/`NOMINMAX` are already defined on the test command line (C4005 under /WX), so the link test guards its own definitions.

## Deferred

- Locating the sections that have no locator (associative ones) is left to the bind planner / WP-09 (they never need retargeting); PDB section contributions carry addresses (module, start, size) but not the object section index.
- Converting a regular model to bigobj automatically (CML3301 asks the caller to choose).
- Anchoring the binding object itself (not needed: its symbols are publics).
- ARM64/x86 relocation handling in the writer (relocations are written raw; the binding generator is x64 only).
