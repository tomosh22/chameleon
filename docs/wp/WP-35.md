# WP-35: structured file and line on `diag` events (ADR-0040)

A compile failure now names where the first compiler error is, as fields, so the editors need not parse text.

## Shapes

`diag` event for a compile failure (CML2200), before:

```json
{"event":"diag","id":"CML2200","message":"compiling '...logic.cpp' failed with exit code 2: C:\\...\\logic.cpp(12): error C2059: syntax error: ';' First error: ...","action":"...","severity":"error","stage":"compile","pid":123}
```

After (capability `diag-locations`; `file`, `line` only when known, `column` only when the compiler printed one):

```json
{"event":"diag","id":"CML2200","message":"<unchanged>","action":"<unchanged>","severity":"error","stage":"compile","pid":123,
 "file":"C:\\...\\logic.cpp","line":12,"column":15}
```

The failed `reload` answer, before `{"id":N,"ok":false,"diag":{"id","message","action"}}`, after the same plus `file`, `line`, `column` inside `diag` under the same rules. Nothing that existed changes; diagnostics without a position (D8003 command-line errors, link and bind failures) have none of the three fields.

* `file` is absolute: the compiler's own spelling, joined with the compile record's working directory when it was relative.
* cl prints a column only with `/diagnostics:column`, which Chameleon's rewrite drops, so under cl there is no `column`. clang-cl prints one.
* The position is the first error (severity error or fatal error) of the parsed `toolchain::ToolDiagnostic` list, the one already named in the message ("First error: ..."). The text is never re-parsed in the broker.

## Design: where the location travels

Options: (a) an optional location next to the Diag in `Result<PatchReport>` / the pipeline failure path, (b) optional fields on `cml::Diag`. Chosen: (b), `Diag::file`, `Diag::line`, `Diag::column` (`has_location()`).

* The failure already travels as a `Diag` through five hand-offs: the compile cache (`CompileCache::Entry::error`, so a reused failure keeps its place), `fail()` which publishes the event, `Result<PatchReport>`, the reload service (which appends "(N of M modules failed)" to a copy) and `make_error_response`. Option (a) would need a parallel channel through every one of them and through the cache.
* Cost: a `std::string` and two `uint32_t` per Diag, empty and zero for every other diagnostic (no allocation for an empty string). `Diag::make`, `id()`, `format()` and `valid()` are untouched; `format()` never prints the location, so no existing text changes.
* Only the compile stage sets it (`pipeline.cpp`, `locate()`), right where "First error" is already named.
* Wire: `ControlDiag` gets the same three optional members; `event_bus.cpp` (`make_diag_event`) and the answer encoder write them only when set; the decoder and `to_diag` read them back. The capability name is `ipc::capability::kDiagLocations` = `"diag-locations"`, one entry in `control_server.cpp`.

## Extensions and the fallback rule

* VS Code: `problemsOfDiag(event)` (`src/format.ts`): when the event has a non-empty string `file` and an integer `line >= 1`, it yields exactly one Problems entry at that file and line (column when `>= 1`); the compiler's code and text are taken from the message's first compiler line for wording only. Otherwise (older broker, or a diag without a position) it falls back to `parseDiagnostics(message)`, the regex parse as before. `Diag` (the error answer) also keeps `file`/`line`/`column`.
* Visual Studio: `DiagnosticLocation.TryFromFields` is tried first for the `diag` event and the error answer (`EventFormatter`); on failure `DiagnosticLocation.TryParse(message)` runs as before. `ErrorListSink` already turns `OutputLine.Location` into the task (Document, Line - 1, Column - 1, navigate), so it needed no change.
* Rule: structured fields win only when both `file` and `line` are usable. The decision is by the fields' presence, which is equivalent to the capability because only a broker with `diag-locations` sends them.
