# WP-19: ImGui broker UI (`cml_ui`)

Architecture: ADR-0033 (`docs/DECISIONS.md`). `cml_ui.exe` is a client of the broker's control pipe only; it never links
`cml_core`. Diagnostics: CML5700-5713 (ADR-0032 range 5700-5749).

## What was built

| Piece | Where | Notes |
|---|---|---|
| `cml_ui_core` (static, portable) | `broker/cml_ui/{include,src}` | Window-free. Built and unit-tested in every cell (and on Linux with `CML_ALLOW_NON_WINDOWS`). |
| Compile-output parsing | `compile_output.*` | `file(line[,col]): error|warning|fatal error|note CODE: text` (cl, clang-cl), `file:line[:col]: error: text` (clang style, drive letters handled), `x.obj : error LNK2019: ...` (linker; shown, not clickable). |
| Editor command templating | `editor.*` | Presets `code -g {file}:{line}:{col}` and `devenv /edit {file} /command "Edit.GoTo {line}"`, or a custom template with `{file} {line} {col}` (`{{`/`}}` literal braces). The command is an argument vector, never a shell string. |
| Settings | `settings.*` | `%APPDATA%\Chameleon\ui.json`; forgiving load (bad member keeps its default and warns), atomic save (temp file + rename). Hotkey text parser (`Ctrl+Alt+F11`). |
| Command table | `commands.*` | One row per control command the UI drives: `status reload wait set-option subscribe` (WP-12..16) and `exceptions exception-action restart revert` (ADR-0032, gated on their capability). `uncovered_capabilities()` is the "does the UI cover every capability the broker advertises" check. Request builders and result parsers (`reload`, `restart`, `revert`). |
| View model | `view_model.*` | All panel state: process/module list, output lines, patch history, change list, log (bounded, level + text filter), pending exceptions, confirm prompt, progress, status line. Events are reduced here (`diag`, `patch_applied`, `progress`, `log`, `exception`, `restarted`, `patch_reverted`). Mutating members lock a recursive mutex; the UI thread holds `lock()` for a frame. |
| Controller | `controller.*` | Runs a command through a `Transport` interface, gates it on the capability, turns an error response into a `Diag`, and feeds the answer into the view model. `CML5402` (unknown command) or a missing capability disables the feature instead of failing. The unit tests drive it with a scripted fake broker that speaks the WP-12 and ADR-0032 shapes. |
| Windows front-end | `broker/cml_ui/src/win` | `broker_link.*` (control-pipe transport, starting `cml_broker.exe`, a command thread and an event thread), `editor_launch.*` (`CreateProcessW`, no shell), `app.*` (window, Direct3D 11, ImGui, tray, hotkey, single instance), `self_test.*`, `main.cpp`. Built only with `CML_BUILD_GUI=ON` (CI always). |
| Tests | `tests/unit/ui` (`unit.ui`, 58 cases), ctest `ui.self_test` | |

## How to run

* `build\bin\cml_ui.exe` (needs `cml_broker.exe` next to it, or a running broker). `--minimized` starts in the tray, `--settings FILE` uses another settings file.
* Unit tests: `ctest --test-dir build -C <config> -R "^unit\.ui$"`.
* Self-test: `ctest ... -R "^ui\.self_test$"`, or by hand `cml_ui.exe --self-test --broker build\bin\cml_broker.exe [--work-dir DIR]`. It starts the broker on private pipes, connects, runs `status`, subscribes on a second connection, makes `reload` fail with CML5300 and checks that the diag event arrives and is shown exactly once, sets options and waits, feeds the ADR-0032 event shapes through the view model, checks the editor command lines and the settings round trip, and checks that `uncovered_capabilities()` is empty. It creates no window. The result line is `CMLUI_SELFTEST result=ok checks=N failures=0`.

## Control commands and what the UI does with them

| Command / event | UI |
|---|---|
| `status` (polled every 1.5 s, and after each action) | process and module list; module index state (`loading n%`, `ready`, `failed`); capabilities; connection badge |
| `subscribe` (own connection; events `diag patch_applied progress log`, plus `exception restarted patch_reverted` when the capability is advertised) | output panel, change list, patch history, log view, progress bar, exception modal |
| `reload` | Reload button (selected process/module, or all), global hotkey, tray menu, "Recompile all" after CML5551 (`"confirm": true`) |
| `wait` | Broker menu: wait for idle / module indexes |
| `set-option` | settings: `compile_on_save`, `max_parallel_compiles` (jobs), `max_affected_compilands`; sent on connect and on every settings change |
| `exceptions`, `exception-action` (ADR-0032, capability `exceptions`) | modal with Continue / Leave function / Ignore (the buttons follow the event's `actions`) |
| `restart` (capability `restart`) | Restart process button with a confirmation |
| `revert` (capability `revert`) | Revert last / Revert all buttons (all asks first) |

A command the broker does not advertise leaves its button disabled with a tooltip; a command answered with CML5402 disables
itself for the rest of the connection.

## Decisions

* **`cml_ui` is a GUI-subsystem exe with a testable core.** Everything that decides anything lives in `cml_ui_core`; `app.cpp` only draws and wires Win32. `--self-test` writes to the inherited standard-output handle with `WriteFile` because a GUI-subsystem process has no console.
* **Two control connections.** `reload` can block for a minute; events must keep flowing meanwhile. One connection runs commands and polls `status`; the other only subscribes. A diagnostic that arrives both as the error response and as a `diag` event is merged into one set of output lines (either order).
* **Capabilities drive the UI.** The subscribe list is built from the advertised capabilities because the broker rejects unknown event names; `exceptions`, `restart`, `revert` stay disabled until a broker advertises them.
* **Editor launching never uses a shell.** `code` on Windows is `code.cmd`; the launcher resolves it to `Code.exe` (one level above `bin`) or the default install paths, and refuses any `.cmd`/`.bat` (CML5712) because batch files re-parse their arguments.
* **Broker start.** When nothing answers on the control pipe the UI starts `cml_broker.exe --headless` from its own directory (no idle timeout, so it keeps running when the UI closes; the agent attaches to it) and retries for up to 12 s, at most once every 20 s.
* **Dear ImGui stays at v1.93.0** (vendored by WP-01; `third_party/imgui/VERSION` records it). The brief named v1.91.5; downgrading buys nothing and the code uses 1.93 API (`FontScaleDpi`, `ImGuiChildFlags_Borders`).
* **The self-test starts its own broker** (`--broker PATH`) instead of the ctest starting it, so one ctest entry is enough and the broker is killed through a job object on every exit path.
* **Hidden window and exceptions.** When the window is hidden in the tray and an exception event arrives, the window is shown (an unanswered exception freezes the target thread).

## Deferred / limitations

* **Enable/disable toggles are read-only.** The control protocol has no `enable-module`/`disable-module` command (the application enables modules through the agent). Adding one is a broker change (`control_server.cpp`, `session`) outside this package's files. The UI's table, view model and button wiring are ready for it: a new row in `command_table()` plus one `Controller` method.
* **The change list is thin for compile-on-save.** The broker publishes no "file changed" event, and `patch_applied` carries no file names or timings. The list therefore shows files named by reload answers this UI requested, patched modules (from `patch_applied`) and watcher diagnostics (`stage: "watch"`). Timings of saves that the broker triggers itself are missing from the history table ("-"). Fix: add `changed_files` and `timing_ms` to the `patch_applied` event (additive, `event_bus.*` / `pipeline.cpp`).
* **Visual acceptance is manual** (see checklist); no screenshot tests, as the plan says.
* **No installer, no autostart, no localisation.** The tray icon is the stock application icon.
* **Hotkey changes** re-register immediately; a hotkey owned by another program is reported (CML5706) and the UI keeps running without one.
* **Large outputs.** Output (10000 lines), log (5000), history and changes (500) are bounded; older entries are dropped.
* **A broker that is not the same version** is not detected beyond capability gating; the UI shows the broker version in the About box.

## Learned

* `std::filesystem::u8path` is deprecated in C++20 and MSVC turns that into an error under `/WX`; settings paths are built from `std::u8string`.
* `Result` is `[[nodiscard]]`: every fire-and-forget controller call inside the UI is an explicit `static_cast<void>`.
* With mingw-w64 and wine the whole self-test ran end to end against the real broker before CI (mingw needs `-municode`, `__USE_MINGW_ANSI_STDIO` and a `_dupenv_s` shim; none of that applies to the MSVC/clang-cl builds). The window code was compiled (mingw, `-Wall -Wextra -Wpedantic`) but never run.

## Review fixes (round 1)

1. `compile_on_save` is `optional<bool>` (default: leave the broker's value); only options the user set are sent, on connect and on change.
2. Output dedup compares diag id and the whole message (`OutputLine::full_message`), so same-id diagnostics with other text are never dropped; the response/event pair is still shown once.
3. `ViewModel::try_begin_reload()` is the single guard (connected, `reload` advertised, nothing running; reserves the slot so triggers cannot queue). Button, menu, hotkey, tray and the confirm prompt all use it.
4. `set_pending_exceptions` replaces the list (the `exceptions` answer is authoritative); losing the connection clears it.
5. One CML5551 prompt per reload request (`reload_serial_`): a late event or answer of an answered request does not re-arm it.
6. `exception_action` resolves the exception on CML4400/CML5751 (thread gone); other refusals (CML4401/4402, unreachable agent) keep it pending.
7. The log-level filter now also sets the broker's `log_level` when lowered to trace/debug, and restores `info` when raised again (`settings_change_options`).
8. The connection epoch is bumped before `Connected` is published.
9. A relative file in a compiler message is looked up below the directories of the broker-reported modules (and up to four parents); a hit becomes the editor's working directory. The broker's diagnostics carry no compile directory, so without a hit the editor starts in the UI's directory (limitation).
10. Error/warning counters are kept in `push_output`/trim/clear (O(1)).
